# Legacy to Spec：翻新哲學

## Goals

1. **Primary**：產出可理解、可追溯、可驗證的技術中立系統契約與視覺成果，保留已有證據的意圖和體驗。
2. **Secondary — 依賴與增量**：先建立翻新計劃，再辨識外部資源、依賴與影響；重用適用契約，依使用者決策逐步補齊缺口。
3. **Secondary — 分離與維護**：分離系統設計、跨邊界契約與翻新執行紀錄，讓每次小範圍交付可持續維護。

## Constraints

- **Scope**：每輪只有**一個入口來源**；依賴分析不自動授權擴大翻新範圍。
- **Evidence**：**不以推測補造**行為、意圖或外部能力；未建立、未知與衝突保留可定位的缺口。
- **Instruction Boundary**：本文件只定義**翻新哲學**。來源技術、領域知識、程序與交付細節放在**按需引用的參考文件**。

## Rules

翻新的成果是**可理解、可追溯、可驗證的系統契約**。以系統在特定情境下接收什麼事件、做出什麼反應，以及使用者能觀察到什麼結果，取代對既有實作語法的重述。

`R*` 識別本文件的規則，`E*` 識別原則示例；與交付文件中的證據識別碼分開。既有編號保持穩定，新增規則或示例接續編號，不因調整順序重編。

### R1: 證據先於描述

- **REQUIRED**：只有**直接來源、可重現觀察或可定位的確認紀錄**能支撐行為主張。缺少依據時保留問題與其影響；衝突時保留各方證據。
- **FORBIDDEN**：命名、慣例與經驗只能協助尋找證據，**不能代替證據**。缺少依據時**不生成看似完整的答案**；衝突時**不自行裁決**。

### R2: 保留意圖與體驗

- **REQUIRED**：保留**資訊層級、操作順序、狀態變化、回饋、限制、資料副作用及跨邊界互動**。事件的**作用範圍、時間關係與生命週期**也是契約。業務意圖必須有依據；只看見操作時就只描述操作，不擴張成未確認的目的。**原有缺陷和改良提案分開記錄**，不藉翻新悄悄改變契約。
- **FORBIDDEN**：不能因展示方便改變**觸發對象、取消時機或中間狀態**。

### R3: 權威依責任分配

- **Authority**：畫面、互動與共用呈現以**前端來源**為權威；服務能力、交換契約與業務處理以**後端產物**為權威。
- **REQUIRED**：跨邊界需求要**同時保留兩端依據**，不能由一端的期待補造另一端的能力。指定適用版本並分清**既有事實、設計承諾與展示替身**；有矛盾時揭露差距，不任意改寫任一端的契約。

### R4: 耦合必須拆責任

- **REQUIRED**：同一來源承載多種責任時，先還原**事件、資料來源、判斷、順序與副作用**，再逐項界定責任。**執行位置不等於責任歸屬**。
- **Responsibility**：呈現留給前端，業務決策與受信任狀態交由後端；尚未被後端承接的行為形成**有證據的移交需求**，不在前端重製，也不假定已有可用邊界。

### R5: 以觸發與結果組織契約

- **REQUIRED**：每個流程說明**觸發者、事件、前置狀態、條件、系統反應、可見結果及後置狀態**。使用者、系統生命週期與外部回應皆可能觸發流程。
- **Branch Preservation**：不同條件產生不同結果時，**保留各分支**；未知分支不得偽裝成成功路徑。某個情境是否成立未知時，仍保留各已證實分支的反應，不能整體省略。

### R6: 先計劃，再沿依賴推進

- **Plan First**：先留下**入口、初始邊界與任務計劃**，再分析依賴並更新影響。每項任務記錄**依賴、影響範圍與驗證條件**。
- **Reuse and Decision**：已有適用規格**直接引用其版本和使用範圍**；尚未轉換的依賴納入計劃，告知使用者缺口與影響，由使用者決定**先翻新或延後**。沿用已有明確授權，**不將沉默當作決策**。
- **Deferred Gap**：延後時在**受影響契約位置保留 TODO**，並連到計劃中的後續處理。

### R7: 小範圍累積

- **Scope**：每次以**一個入口來源檔案**建立可控邊界。依賴可以支撐理解，但不能自動擴張為另一個翻新單位。
- **Traceability**：尚未建立、未能取得或未確認的部分留在**獨立追蹤紀錄**中，後續以**穩定識別碼**補充，不覆蓋既有證據與決策。

### R8: 契約與執行分離

- **Separation**：設計規格描述**系統應有的可觀察行為**；翻新追蹤描述**分析、待辦、驗證與進度**。兩者透過識別碼互相連結，不把工作排程寫成系統需求。
- **Style Consistency**：有樣式設計的元件**同時交付可追溯的樣式契約與視覺成果使用的樣式**，兩者逐項核對；客製化不改變證據要求或權威歸屬。
- **Consistency**：視覺原型與文字契約共用**同一套行為事實**；展示用資料與審閱工具不能變成新需求。

### R9: 完整性必須能被檢查

- **Evaluation Basis**：完整性以**已界定範圍的證據、流程、狀態、互動與驗證覆蓋**判定，不以篇幅判定。**沒有發現不等於不存在**；尚未取得的資訊不等於不適用。
- **Partial Delivery**：必要行為仍有缺口時，交付**可追蹤的部分成果並說明限制**，不宣告完整。

## Examples

以下只示範原則的適用方式，不定義任何領域行為。

### E1: 已知觸發，未知結果

- **已知條件**：來源證明一個事件會引發外部交接，但未取得交接後的結果。
- **CORRECT**：描述已知觸發與傳遞資訊；將未知結果及影響連到缺口與後續查證。
- **INCORRECT**：把未取得的結果描述成成功，或因結果未知而省略已知觸發。
- **對應規則**：[R1](#r1-證據先於描述)、[R5](#r5-以觸發與結果組織契約)、[R9](#r9-完整性必須能被檢查)。

### E2: 適用契約與未轉換依賴

- **已知條件**：一項依賴有適用契約，另一項尚未轉換，且使用者尚未決定如何處理。
- **CORRECT**：引用已核對的契約；記錄另一項依賴的缺口與影響，告知使用者並維持待決，只繼續不依賴該決策的工作。
- **INCORRECT**：重複翻新適用契約，或把未回覆視為同意擴大範圍或延後。
- **對應規則**：[R6](#r6-先計劃再沿依賴推進)、[R7](#r7-小範圍累積)。

### E3: 需求存在，承接未確認

- **已知條件**：呈現所需能力有來源證據，但負責處理該能力的一方尚未提供承接依據。
- **CORRECT**：保留已知呈現需求、責任界線與具體移交缺口；展示停在已知邊界。
- **INCORRECT**：由呈現需求推導處理能力已存在，或把展示替身視為已承接的證據。
- **對應規則**：[R3](#r3-權威依責任分配)、[R4](#r4-耦合必須拆責任)、[R8](#r8-契約與執行分離)。

## Workflow

依 [工作方法](guides/workflow.md) **先建立計劃、確認依賴決策**，再形成契約與視覺成果，最後驗證並更新追蹤。續作**沿用識別碼與既有決策**，回查來源和依賴版本變動；流程細節由參考文件定義。

### 按需引用

- **開始或續作翻新**：讀 [工作方法](guides/workflow.md)，選用範本並建立邊界。
- **查找既有依賴契約或遇到未轉換資源**：讀 [依賴與決策](guides/dependencies.md)，先核對可重用性與影響。
- **選定各類權威與參考既有轉換設計**：讀 [權威分工](references/api/authority.md)；相關來源背景見 [後端設計參考](references/api/backend-profile.md)。
- **轉寫服務交換契約**：讀 [介接契約方法](references/api/writing-rules.md)。
- **單一來源混合多種責任**：讀 [耦合拆解方法](references/legacy/responsibility-rules.md)。
- **判斷事實、未知、衝突及術語**：讀 [證據規則](guides/evidence.md)。領域知識的引用條件也定義於此。
- **分析特定來源形式**：讀 [來源解析參考](references/legacy/jsp-analysis.md)。技術細節只存在於參考文件。
- **選用或客製可重用範本**：讀 [範本客製化](guides/customization.md)，實際成果另存。
- **建立或核對視覺成果**：讀 [視覺契約](references/ui/writing-rules.md)；有元件樣式時讀 [樣式契約](references/ui/style-spec.md)。
- **判斷是否可交付**：讀 [驗收規則](guides/acceptance.md)。

## Output Format

依工作方法選用範本，**分別維護**系統行為規格、視覺成果、適用的跨邊界契約、翻新計劃與執行追蹤。以**穩定識別碼和有效連結**連接成果；**缺口標記放在對應契約位置**，處理進度與決策留在計劃及追蹤。

## Evaluation Criteria

- [ ] **證據與覆蓋（R1、R2、R5）**：已界定的行為、分支、互動與副作用有證據及驗證去向。
- [ ] **依賴與決策（R3、R4、R6、R7）**：任務依賴與影響可追蹤；重用契約適用，未轉換資源有明確決策或待決狀態。
- [ ] **局部缺口（R6、R7）**：延後依賴的缺口在實際受影響位置可見，且可連到後續處理。
- [ ] **樣式與客製化（R8）**：元件樣式契約與視覺成果實際使用的樣式有映射與驗證；客製範本版本可追溯。
- [ ] **交付一致性（R8、R9）**：文字與視覺成果一致；必要缺口未解或驗證不足時如實標為部分交付。
