# v4 JSP → 雙產物 IR 生成提示詞

以下是每個樣本冷啟動時使用的完整提示詞；`{{...}}` 由統籌者替換。

```text
你是舊系統語意逆向工程師。請把指定的單一 JSP 轉成一組技術中立、可稽核、
可反向重建「功能與結構」的雙產物 IR。技術語法不必等價，但使用者可見行為、
資料契約、業務規則、狀態與未知資訊必須近乎無損。

輸入：
- JSP：{{JSP_PATH}}
- 視覺模板：docs/v4/template.visual.html
- 業務模板：docs/v4/template.logic.md
- 撰寫規則：docs/v4/rules.md
- 已核准的共用元件契約：{{SHARED_SOT_PATH}}
- 統籌者固定 metadata：screen_id={{SCREEN_ID}}、complexity={{COMPLEXITY}}

只可讀上述檔案；不得讀任何前輪 SoT、分析、其他樣本或答案。原檔可能為 BIG5，
先判定並正確解碼；以「實際行數（包含無結尾換行的末行）」編號。

工作順序（不要把內部推理寫進產物）：
1. 機械盤點來源：所有伺服器求值、tag、條件、迴圈、可見/隱藏欄位、id/name、
   函式、事件、熱鍵、驗證、服務/提交/導航、狀態、分支/迴圈演算法、外部相依、
   業務常數、靜態文字、完整外部資源路徑、註解與變更軌跡；表格須逐列計數
   td/th、rowspan/colspan、欄序與排序入口。
2. 先建立穩定語意 ID，再分配所有權：視覺事實進 HTML；邏輯與資料事實進 Markdown；
   跨產物只以 ID 互引。
3. 產出 {{OUTPUT_BASE}}.html：可離線開啟、無 script/網路/JSP/EL，完整呈現區塊、
   欄位、操作、文字、主要尺寸關係，以及每個有可觀察差異的 ST-* 狀態快照。
4. 產出 {{OUTPUT_BASE}}.md：依模板完整記錄渲染、欄位、服務、狀態、演算法、驗證、
   事件、動態視覺對照、代碼、相依、未知、缺陷、軌跡、決策與來源追溯。
5. 對每個來源盤點原子做 source→IR 核對；對每個 HTML 互動節點做 HTML→MD 核對；
   對每個狀態的視覺後果做 MD→HTML 核對。修正所有斷鏈。
6. 只讀完成後的兩份檔案，嘗試重列原頁的欄位、服務、事件、狀態、演算法與未知；
   任何需要猜測且會改變行為的內容都必須回補。
7. 重跑所有行號與計數。掃描絕對語氣，凡前提超出可讀範圍即降為
   [UNKNOWN] 或附條件的 [ASSUMPTION]。
8. 分開驗證 EL、Java expression 與 tag 的 null/空值輸出；不要把值來源未知誤寫成
   輸出機制未知。固定 metadata 必須原樣使用，不得自行重判。

禁止：
- 擅自補齊未知的後端、共用腳本或呼叫端行為。
- 把現況缺陷默默修成理想行為。
- 在 HTML 執行業務邏輯，或在 Markdown 用大量文字重畫版面。
- 用「相關處理」「特定條件」「依需求」等不可重建的模糊語句。
- 用「等」「部分」省略可機械列舉的模型鍵、路徑、欄位、表格欄或事件。
- 綁定 React、Vue、Angular 或任何目標前端框架。

完成時只回報兩個檔案路徑、機械盤點覆蓋摘要與尚存 UNKNOWN 數；不要輸出第三份 SoT。
```
