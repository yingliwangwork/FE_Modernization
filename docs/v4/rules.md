# 雙產物 IR 撰寫規則 v4

v4 的原子單位是同名的一對檔案：`<畫面>.html`（視覺契約）與
`<畫面>.md`（業務與互動契約）。兩者合起來才是 SoT；任何一份都不是完整 SoT。

## A. 所有權與去重

1. HTML 擁有：可見文字、區塊階層、欄位順序、群組、主要尺寸關係、可編輯外觀、
   可見/隱藏/啟用狀態與代表性資料。
2. Markdown 擁有：資料來源、顯示/送出格式、渲染條件、狀態轉換、事件、驗證、
   服務、演算法、隱藏資料、相依、未知、缺陷、來源追溯。
3. 跨界資訊只用穩定 ID 連結。HTML 不抄業務條件運算式，Markdown 不以文字重畫版面。
4. 同名 `.html` 與 `.md` 必須互相宣告 companion 路徑，`screen_id` 必須相同。

## B. ID 契約

1. ID 前綴固定：`V-` 可見區塊、`F-` 欄位、`E-` 使用者動作/事件目標、
   `ST-` 視覺狀態、`MSG-` 訊息、`R-` 渲染規則、`S-` 服務、`A-` 演算法、
   `VR-` 驗證、`T-` 狀態轉換、`U-` 未知、`D-` 缺陷、`DEP-` 相依。
2. HTML 的 `data-ir-id` 全檔唯一；重複列以容器 ID + 欄位 ID 描述，不複製 DOM id。
3. Markdown 引用視覺 ID 時必須原字匹配。非視覺資料使用 `F-HIDDEN-*`，不得假造 HTML 節點。
4. 原始 DOM id/name 保留在 Markdown 來源欄，不得直接當唯一 IR ID，以免來源本身重複。

## C. HTML 視覺契約

1. 必須是可離線開啟的完整 HTML5 文件；不得依賴外部 CSS、字型、圖片或腳本。
2. 禁止 `<script>`、JSP/scriptlet/EL、網路請求、表單實際提交、驗證與業務計算。
3. 使用語意 HTML；只有原始表格確實承載二維資料或表單群組時才保留 table 語意。
4. 保留來源的資訊階層與操作順序；可清理無行為意義的相容性標記或壞 HTML，
   但這些來源缺陷仍須記在 Markdown §14。
5. 所有可見靜態文字、欄位、欄標、代碼說明、按鈕與訊息原文不得摘要。
6. 每個重大可觀察狀態各自建立 `ST-*` 快照：初始、已載入、空結果、錯誤、
   權限/條件造成元素不存在、編輯/唯讀、選取/未選取等。只在值不同時可共用骨架。
7. Mock data 必須明標為示例，不得冒充來源事實；格式、長度與空值外觀需符合來源契約。
8. HTML 可以用 `data-visible-when="R-*"`、`data-action-id="E-*"` 等引用 ID，
   但屬性值不得放條件運算式、endpoint 或演算法。
9. 重複資料區必須同時保留列範本、欄序、cardinality/key/序號規則與空集合快照；
   來源重複 DOM id 不得帶入成重複 IR ID，須改以 `data-defect-ref` 追溯。
10. 無效來源 HTML 預設呈現瀏覽器可觀察的修復後結果；來源寫法與修復不確定性記在 Markdown。

## D. Markdown 業務契約

1. 伺服器渲染與瀏覽器互動分開記錄；每個求值、條件與迴圈必須覆蓋。
2. 每個欄位同時記顯示、編輯、送出三種角色；唯讀但會送出的欄位不得遺漏。
3. 每個服務列出位址/方式/觸發/逐項請求/逐項回應/成功/失敗/時序/編碼。
4. 每個分支、迴圈、累加、排序、重編、格式轉換與 DOM 搬移寫成可重建的虛擬碼。
5. 內嵌事件必須記錄是否阻止預設行為及對捲動、歷程、提交的後果。
6. `UNKNOWN` 與 `ASSUMPTION` 規則沿用 v3：只要結論有一項前提在可讀範圍外，
   就不能寫成無條件事實；推論須附證據與成立條件。
7. 缺陷不得默默修正或正規化。先記現況，再列需人決定的「保留/修正」。
8. 內容注入、未編碼 URL、列印/防拷/浮水印/稽核等安全行為必須進 §14 與 §16。
9. EL `${...}`、Java expression `<%=...%>`、JSTL/自訂 tag 的 null/空值語意不得互套；
   能由輸出機制確定的行為不可因值來源未知而整欄標 UNKNOWN。
10. 外部資源與服務位址保存完整相對/絕對路徑，不得只寫 basename 或「等」。
11. 死碼分級固定為 `[SUSPECTED-DEAD-CODE]` 與 `[DEAD-CODE-PROVEN]`；後者必須證明
    無直接呼叫、無載入副作用、無外部消費者、無反射/名稱式存取。

## E. 完整性程序

生成前先建立但不輸出的來源盤點：求值點、tag、條件、迴圈、欄位、name/id、
函式、事件、服務/提交/導航、狀態、外部相依、註解與硬編碼業務值。

生成後依序執行：

1. 來源 → IR：每個盤點原子在 §17 有且只有一個主落點。
2. IR 內部：所有 ID 唯一且引用可解析。
3. HTML → Markdown：每個互動節點有欄位、事件或驗證契約。
4. Markdown → HTML：每個可觀察狀態後果有節點或快照。
5. IR → 行為清單：只讀這一對檔案，重列欄位、服務、事件、狀態、演算法、未知與缺陷；
   若無法唯一重列，視為規格不足並補寫。
6. 所有行號與數量以指令重算，不得憑印象。
7. 表格逐列機械計數 `<td>/<th>`、rowspan/colspan、欄序與可排序入口；不得以
   「N 欄」「部分可排序」取代完整映射。
8. 固定樣本的層級、路徑等研究 metadata 由統籌者注入，不允許生成者自行重判。

## F. 收斂硬門檻

- 高嚴重度語意遺漏：0。
- 欄位、服務、渲染條件、事件、驗證與演算法盤點覆蓋率：100%。
- HTML/Markdown ID 引用完整率：100%。
- 未知資訊被寫成肯定句：0。
- HTML 可離線解析，且不含可執行業務邏輯。
- 反向重建者只讀雙產物時，不需猜測任何會改變可觀察行為或資料正確性的規則。
