# SoT 撰寫規則 v3

與 `docs/v3/template.md` 搭配使用。

v3 相對 v2 的變更來自 `docs/v2/analysis.md`：v2 把遺漏從 33 降到 14，
但暴露了三個新問題——**推論被寫成肯定句**（OVER-2，7 項）、
**三份文件彼此不一致**（GAP-9）、**篇幅膨脹與重複**（OVER-1）。
v3 的重點是把規則從「要求做什麼」改成「**可機械檢查**」。

標記約定：`[UNKNOWN]` 未知、`[DEFECT]` 現況缺陷、`[DEAD-CODE]` 死碼、
`[ASSUMPTION]` 推論（必須附推論依據與成立條件）。

---

## A. 根本原則

**A1. 保留功能與結構，不保留實作技術。**

**A2. 判準：一位沒看過原始碼的工程師，能否只憑 SoT 寫出行為一致的畫面？**

**A3. 絕對語氣必須通過前提檢查。**〔v3 修訂〕

v2 的 A3 寫「不知道就標未知」，但沒擋住 7 項過度主張。
失效原因：作者**知道一半**——驗證了本檔範圍內的前提，
就把「本檔範圍內為真」當成「執行期為真」。

因此改為可執行的程序：

> 凡結論句含 **恆／必定／永不／完全／實際上／一律／不可能** 等絕對語氣，
> 須逐一回答：**支撐這個結論的每一個前提，是否都在本輪可讀範圍內？**
> 只要有一個前提落在範圍外，該句一律降為 `[ASSUMPTION]`，
> 並把該前提寫進 §14 未知清單。

**A4. 現況即事實。** 缺陷、死碼、命名不一致一律照實記錄。

**A5. 宣告計數口徑。**〔v3 新增〕
SoT 開頭須宣告行數的計數方式（是否計入無結尾換行的最後一行）。
v2 三份用了兩套口徑，導致統計無法直接比較。

**A6. 同一項事實只在一個章節完整記錄。**〔v3 新增〕
其他章節以交叉引用（`見 §4.3`）帶過，不得複述。
v2 的 §11.1 與 §4.3 逐格重複，是膨脹的主因之一。

---

## B. 執行階段（GAP-1）

**B1.** 伺服器端求值與瀏覽器端執行必須明確分開。

**B2.** 每個伺服器端求值點進 §3，說明落點與前端可否變更。

**B3.** 伺服器端條件渲染與前端顯示/隱藏分別記錄。

**B4.** 顯示格式與送出格式不同的欄位，兩種格式都要寫。

**B5. 宣告式標籤的邊界行為必須記錄。**〔v3 新增〕
凡由標籤庫或平台元件產生輸出的位置（`fmt:*`、`c:*`、自訂標籤），
§3 的「型別/格式」欄須同時記錄三種輸入下的輸出：
**正常值 / 空值或 null / 不可解析值**。不可知時標 `[UNKNOWN]`。

> v2 失效案例：88 個 `<fmt:formatNumber>` 的空值渲染行為整批漏掉。
> 原因是 D4 只要求「演算法」寫邊界條件，宣告式標籤不被視為演算法。

---

## C. 服務契約（GAP-2）

**C1.** 每個後端呼叫獨立一節，六項齊全（位址/方式/觸發/請求/回應/失敗處理）。

**C2.** 請求參數逐一列出，標明每個參數的來源。

**C3.** 「只進不出」的參數另行點明。

**C4.** 失敗處理若原始碼沒寫，寫「無」並標 `[DEFECT]`。不得省略，不得補寫。

**C5.** 後端提供的代碼對照表列進 §11.2。

---

## D. 演算法與狀態（GAP-3）

**D1.** 含迴圈、分支、累加、重新編號、格式轉換的邏輯，一律進 §8 寫虛擬碼。

**D2.** 虛擬碼須標明基準點與初值來源。

**D3.** 累加器要寫清楚是增量維護還是每次重算。

**D4. 邊界條件清單。**〔v3 擴充〕每個演算法都要寫：
- 空值、零筆、全選、型別轉換失敗
- **寫入目標的值域限制**：寫入 `<select>` 的值不在選項中、
  超過 `maxlength`、型別不符

**D5.** 模組級狀態變數進 §7.1。

**D6.** 元素的啟用/停用、顯示/隱藏進 §7.2。

**D7. 內嵌事件處理須註明預設行為。**〔v3 新增〕
HTML 屬性上的事件處理（`onclick` 等）須註明是否阻止預設行為
（`return false` / `preventDefault` / 兩者皆無），及其可觀察後果
（捲動位置、瀏覽歷程、表單送出）。

> v2 失效案例：`<a href="#" onclick="openDetail()">` 無 `return false`，
> 點擊會額外導覽到 `#`，頁面捲回頂端並推入瀏覽歷程。§10 只要求三欄，沒問這件事。

## E. 未知（GAP-4）

**E1.** §14 未知清單不得為空。

**E2.** 下列一律列為未知：本檔未定義且原始碼不在可讀範圍的函式、
呼叫端決定的回呼契約、格式未說明的伺服器資料、外部元件的行為。

**E3.** 每個未知項要寫影響範圍與建議澄清方式。

**E4.** 外部共用腳本列入 §13，標明行為是否已知。

**E5. 查證範圍須獨立成章。**〔v3 新增〕
SoT 結尾須有「查證範圍」章節（§18），明列**已完整讀取**與**明確排除**的檔案。
§15 判定「經查後無」時，須在該章節指出查證方式。

**E6. 未知清單當反查索引用。**〔v3 新增〕
§14 的每一個未知項，都要回頭檢查全文有無依賴它的肯定句。
v2 的 AFY10100 列了 27 項未知、12 項範圍外相依，`[ASSUMPTION]` 卻只有 4 個
——形式上遵守了每條規則，實質上推論被藏進肯定句。

---

## F. 常數（GAP-5）

**F1.** 硬編碼字面值進 §11.1。

**F2.** 條件分支的比較值要寫代碼本身，不能只寫中文語意。

**F3.** 畫面上的靜態代碼說明文字完整抄錄。

**F4. §11.1 的收錄範圍。**〔v3 新增〕
只收**承載業務或設定語意**的字面值：
服務代號、動作名、參數名、代碼值、閾值、逾時、鍵碼、外部資源路徑、畫面代號與標題。
**純版面屬性值（寬度、`colspan`、`rowspan`、對齊、邊框）一律只記在 §4.3**，不進 §11.1。

> v2 失效案例：F1 的「所有」無界，導致一份全抄（`'10%'` 的 19 個行號都列，與 §4.3 重複）、
> 另一份憑感覺取捨（漏了 10 支腳本路徑）。同一條規則同時造成過度與遺漏。

---

## G. 缺陷（GAP-6）

**G1.** §15 不得為空。

**G2. 機械列舉，不靠肉眼掃描。**〔v3 修訂〕
下列各項須以指令逐一列舉後登記，並在 §18 附上所用指令：

| 缺陷類型 | 列舉方式 |
|---|---|
| 重複 DOM 識別碼 | `grep -o 'id="[^"]*"' \| sort \| uniq -d`，**另須檢查迴圈內的所有 id**（執行期必然重複） |
| 未使用的載入項 | 比對 `<script src>` 與全檔函式呼叫 |
| 無 `name` 的表單元素 | 列舉 `<input>`/`<select>`/`<textarea>` 後比對 |
| 同一屬性的大小寫變體 | 同名屬性值正規化後比對 |
| 未處理的錯誤路徑 | 列舉所有非同步呼叫，逐一檢查失敗分支 |

**G3.** 每項要寫「再工程處置建議」：保留現況 / 修正（需業務確認）。

**G4.** 用字不一致視為缺陷。

**G5. 登記門檻。**〔v3 新增〕
§15 只登記能指出**可觀察行為後果**或**明確維護風險**的項目。
純寫作風格觀察（指令位置、運算子繞路）移入 §16.1 來源歷史。

**G6. 行為後果等級。**〔v3 新增〕
§15 每列加一欄「行為後果等級」：
**影響資料正確性 / 影響使用者可見行為 / 僅影響維護**。供 §17 排序使用。

## H. 版面（GAP-7）

**H1.** 樣式名稱對映到語意。
**H2.** 欄寬、`colspan`、`rowspan`、對齊方式記錄在 §4.3。
**H3.** 逐欄位套用的樣式要標明套用到哪些欄位。
**H4.** 顯示元素＋隱藏元素成對的模式要明寫。

## I. 軌跡（GAP-8）

**I1.** 檔頭註解完整搬進 §0 與 §16。
**I2.** 帶單號或日期的變更註記連同程式位置進 §16。
**I3.** 版型痕跡、產生器註解記在 §16 或 §0 備註。

---

## J. 落地決策點

**J1.** SoT 不替目標技術做決定，列進 §17。

**J2.** 典型決策點：伺服器渲染值的承載方式、以 DOM 為真實來源的機制、
整頁送出改非同步、現況缺陷保留或修正。

**J3.** 資安相關的機制（列印管制、防拷、浮水印、稽核）
一律列為決策點並註明「不可逕行移除」。

---

## L. 跨文件一致性（GAP-9）〔v3 新增〕

v2 的結構性問題：同一個 `header.jsp`，三份 SoT 分別登記了 8 / 4 / 0 項缺陷；
同一個「scriptlet 與 EL 混用」只在一份被登記；
同一命題在一份標 `[ASSUMPTION]`、另一份寫「必定」。

**L1. 共用引入檔抽成獨立 SoT。**
`header.jsp`、`msgDisplayer.jsp` 的行為與缺陷寫成**一份共用元件 SoT**。
各畫面 SoT 只寫三件事：引用了什麼、本畫面的實際條件值、本畫面受影響的具體行為。

> 這同時解決 OVER-1：v2 的 DSC80106 有 13% 篇幅是引入檔行為的複寫。

**L2. 同類缺陷的登記判準須一致**，判準寫在共用規則而非各文件內。

**L3. 同一命題在不同 SoT 中的標註強度須一致**（肯定句 / `[ASSUMPTION]` / `[UNKNOWN]`）。

## K. 產出檢查清單

### K.1 存在性檢查（v2 既有，實測有效，保留）

- [ ] §3：原始碼中每一個 `${...}` / `<%= %>` 都有對應列
- [ ] §3.1：每個條件輸出的元素都有列
- [ ] §5：每個輸入/顯示元素都有列，且「送出」欄已填
- [ ] §5.1：顯示與送出不一致者已逐項列出
- [ ] §6：每個後端呼叫都有「失敗處理」列
- [ ] §7.1：每個模組級變數都有列
- [ ] §8：每個含分支或迴圈的邏輯都有虛擬碼與邊界條件
- [ ] §9：每條驗證規則都有觸發時機
- [ ] §10：每個熱鍵都註明目標元素的存在條件
- [ ] §11.1：每個**承載業務或設定語意**的字面值都有列（版面屬性值不收）
- [ ] §11.2：畫面上的代碼說明文字已完整抄錄
- [ ] §13：每個外部腳本都有列，且標明行為是否已知
- [ ] §14：未知清單非空
- [ ] §15：缺陷登記非空，每列都有「行為後果等級」
- [ ] §16：檔頭註解與變更註記已搬入
- [ ] §17：決策點已列出
- [ ] §18：查證範圍已列出（已完整讀取 / 明確排除）

### K.2 正確性驗證〔v3 新增〕

v2 的 5 項事實錯誤**全部**是「憑印象補的行號與計數」。
§K.1 全是存在性檢查，沒有一條要求回頭驗證已寫下的內容。

- [ ] 每一個引用的行號區間，都回原始碼 `sed -n 'N,Mp'` 確認過一次
- [ ] 每一個出現在文中的計數（「共 N 處」「N 個」），都以指令數過一次
- [ ] §18 附上所用的核對指令

### K.3 過度與失準掃描〔v3 新增〕

- [ ] 關鍵字掃描：全文搜尋 **恆／必定／永不／完全／實際上／一律／不可能**，
      逐句通過 A3 的前提檢查
- [ ] §14 反查：每個未知項都檢查過全文有無依賴它的肯定句（E6）
- [ ] 去重：沒有任何一項事實在兩個章節被完整記錄兩次（A6）
- [ ] §15 門檻：沒有純風格觀察混入（G5）
- [ ] 一致性：與共用元件 SoT 及其他畫面 SoT 的標註強度一致（L3）

### K.4 技術中立

- [ ] 全文無模糊措辭（「特定條件」「某些情況」「相關處理」）
- [ ] 全文無目標框架名稱（Vue / React / Angular）
- [ ] 原始技術名稱只出現在 §13 相依清單與 §15 缺陷定位，未被當成規格
