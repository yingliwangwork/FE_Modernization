# DSC32200 — 劃撥入人工帳

> 來源：`sourceCode/DS/C3/DSC3_2200/DSC32200.jsp`（383 行，BIG5）
> 複雜度層級：中

## 1. 概述

本畫面提供承辦人員登錄「劃撥入人工帳」的暫收款資料。
使用者輸入貸款帳號與暫收原因後，在一張可編輯的明細表中逐筆填入
劃撥日期與金額，系統即時計算合計金額，最後送出確認。

## 3. 畫面結構

### 3.1 條件區

| 欄位 | 型態 | 說明 |
|---|---|---|
| 單位代號/貸款帳號 | 文字輸入 | 失焦時自動轉大寫，最長 10 字元 |
| 暫收原因 | 下拉選單 | 選項由後端提供；預設值 `99` |
| 繳款方式 | 隱藏值 | 固定 `4` |
| 新增 / 刪除 | 按鈕 | 操作明細表 |

### 3.2 合計區

顯示「暫收款資料 合計金額」，隨明細金額變動即時更新。

### 3.3 明細表

可編輯的資料表格，每頁 20 筆，第一欄為可全選的核取方塊。

| 欄位 | 型態 | 說明 |
|---|---|---|
| 劃撥序號 | 唯讀 | 系統編號 |
| 劃撥帳號 | 唯讀輸入 | 固定值 `00041496` |
| 劃撥日期 | 日期輸入 | 民國年格式，附日曆選取 |
| 劃撥金額 | 數字輸入 | 千分位顯示 |
| 備註 | 文字輸入 | 最長 15 字元 |

### 3.4 送出區

「確認」按鈕。

## 4. 驗證規則

| 規則 | 條件 | 訊息 |
|---|---|---|
| 劃撥金額 | 必須大於 0 | 請輸入正確劃撥金額 |
| 劃撥日期 | 必須小於等於系統日期 | 劃撥日期須小於等於作業當時日期 |
| 必填 | 日期、金額、帳號、備註皆為必填 | — |

驗證失敗時聚焦到第一個錯誤欄位。

## 5. 行為

### 5.1 進入畫面

1. 建立頁面外框
2. 初始化驗證規則
3. 建立明細表格
4. 載入一筆預設的空白劃撥資料（序號、帳號、日期由伺服器提供）
5. 合計金額歸零、暫收原因設為預設值
6. 綁定三個按鈕
7. 顯示後端訊息

### 5.2 新增

檢查貸款帳號不可空白，否則提示「單位代號/貸款帳號不可空白!!」。
通過後在明細表尾端追加一筆新的空白資料，序號遞增。

### 5.3 刪除

1. 未勾選任何資料時提示「請勾選欲刪除的電匯資料」
2. 若全選 → 清空明細表並重新放入一筆空白資料，合計歸零
3. 若部分選取 → 移除被選取的資料，**其餘資料的序號重新連續編號**，
   同時重算合計金額

### 5.4 確認

1. 若暫收原因為「入追償款」或「入案款」，先跳出確認對話框，
   要求使用者確認已輸入貸款帳號
2. 執行欄位驗證，未通過則中止
3. 送出明細清單、貸款帳號、暫收原因、合計金額至後端 `confirm` 服務
4. 後端回應分兩種：
   - **有錯誤訊息** → 顯示訊息，並依後端指定的連結目標開啟對應的彈出視窗
     （洗錢防制檢核紀錄 / 可疑交易檢核）
   - **無錯誤** → 若有提示訊息則顯示，接著重置明細表為一筆新的空白資料

### 5.5 金額連動

劃撥金額欄位失焦時：重算合計金額、將輸入值格式化為千分位、回寫至資料物件。
