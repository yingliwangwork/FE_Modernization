## 1. 用途

本畫面供業務人員檢視單一筆「貸款年期變更」申請的完整異動記錄，以唯讀方式並列呈現變更前（原）與變更後（新）的貸款期數、分期期數、定期期數、期別與還款方式，並附上輸入與覆核的人員、日期、單位。
使用者從上游畫面指定一組鍵值（貸款帳號、變更日期、變更種類、序號）後開啟本畫面，用於查核或覆核該筆年期變更的內容。
畫面不提供任何編輯、新增、刪除或送出功能，唯一的操作是關閉視窗回到呼叫端。

## 8. 演算法規格

### 8.1 查詢結果回填（以 DOM 識別碼對映）

**目的**：把後端回傳的資料對映表，逐一寫入表格內對應的顯示區塊。
**輸入**：`resp.rtnMap`（物件）；`table1` 之下的全部 `<div>` 元素（依文件順序）。
**輸出**：23 個 `<div>` 的內容被覆寫；模組變數 `rtnMap` 被賦值。
**虛擬碼**：
```
當查詢回應判定為成功時：
    rtnMap ← resp.rtnMap                         // 基準點：後端回應，非前端既有值

    elements ← 依文件順序取出 table1 之下所有的 div 元素
               // 目前為 23 個，皆為 td 的直接子元素；選取器不限制層級
    對 elements 中的每一個 ele：
        id ← ele 的 DOM 識別碼
        value ← rtnMap[id]
        若 value 為 JavaScript 的偽值（undefined / null / 空字串 / 數字 0 / false）：
            value ← ''                            // 以 || '' 判斷，非以「是否存在該鍵」判斷
        將 ele 的內容整個取代為 value
        // 取代方式為寫入 HTML（非寫入純文字）：value 中若含標籤會被當作標籤解析
```
**邊界條件**：
- **`rtnMap` 缺鍵**：該區塊被寫入空字串，視覺上與「後端回傳空值」無法區分。
- **`rtnMap` 多出的鍵**：畫面上沒有對應識別碼的鍵一律被忽略，不會顯示，也不會有任何提示。
- **後端回傳數字 `0`**：`0 || ''` 的結果是 `''`，因此會顯示**空白**而非 `0`。若任一期數欄位（`LOAN_PERIOD*`、`SPR_PERIOD*`、`FIX_PERIOD*`）以 JSON 數字型別回傳 `0`，畫面會誤顯為空白。`[DEFECT]`（見 §15-4）
- **後端回傳字串 `"0"`**：非空字串為真值，正常顯示 `0`。與上一條的行為不同，取決於後端的 JSON 型別，`[UNKNOWN]`。
- **後端回傳布林 `false`**：同樣顯示為空白。
- **`resp.rtnMap` 本身為 `undefined`**：`rtnMap[id]` 會拋出型別錯誤，中斷整個回填迴圈，已寫入的區塊保留、未處理的區塊維持原狀；錯誤未被攔截。`[UNKNOWN]` 後端是否可能在成功判定下不回傳 `rtnMap`。
- **回應值含 HTML 標籤**：會被當作 HTML 解析並渲染。`[DEFECT]`（見 §15-3）
- **零筆資料**：本畫面為單筆明細，無「零筆」概念；查無資料時的後端行為 `[UNKNOWN]`。
- **重複查詢**：程式僅在載入時呼叫一次，不存在重入或競態。

### 8.2 關閉視窗時的回呼路徑選擇

**目的**：依本頁被開啟的方式，選擇正確的方式把控制權與資料交回呼叫端。
**輸入**：`window.isPopupWin`、`window.popupWinBack`、`window.parent`、`window.parent.popupWin`、模組變數 `rtnMap`。
**輸出**：對呼叫端的一次函式呼叫。
**虛擬碼**：
```
當使用者點擊「關閉視窗」按鈕時：
    若 window.isPopupWin 為真值 且 window.popupWinBack 為真值：
        呼叫 window.popupWinBack(rtnMap)          // 回呼函式名為 popupWinBack
    否則，若 window.parent 為真值 且 window.parent.popupWin 為真值：
        呼叫 window.parent.popupWin.back(rtnMap)  // 回呼物件名為 popupWin，方法名為 back
    否則：
        呼叫 CSRUtil.linkBack()                   // 不傳遞 rtnMap
```
**邊界條件**：
- **查詢尚未回應或查詢失敗時點擊**：`rtnMap` 為 `undefined`，會原封不動傳給呼叫端。呼叫端若未防呆將出錯。`[DEFECT]`（見 §15-14）
- **同源限制**：在 `window.parent` 為跨網域框架時，存取 `window.parent.popupWin` 會拋出安全性錯誤，該錯誤未被攔截，按鈕將無反應。
- **第二分支的 `window.parent` 檢查**：一般視窗中 `window.parent` 恆等於 `window` 自身（真值），因此實際決定分支的是 `window.parent.popupWin` 是否存在。
- **第三分支**：`CSRUtil` 未載入或未定義 `linkBack` 時會拋出錯誤，未被攔截。
- 本函式**不**自行呼叫 `window.close()`；視窗是否關閉完全取決於呼叫端提供的回呼。

### 8.4 回傳訊息的顯示（來自 `msgDisplayer.jsp`，於 `initApp` 中被呼叫）

**目的**：把伺服器渲染時嵌入的訊息串，送到底部訊息框並／或以彈窗提示。
**輸入**：全域陣列 `msgs`（每筆為 7 元素陣列：`[0]` 訊息說明、`[1]` 錯誤編號、`[2]` 程式 ID、`[3]` 型別、`[4]` URL、`[5]` 回傳碼、`[6]` 異常原因）。
**輸出**：底部訊息框的內容更新、與／或一個提示彈窗。
**虛擬碼**：
```
displayMessage()：
    嘗試：
        bottomFrame ← 依序尋找：
            top.leftFrame.bottomFrame → parent.leftFrame.bottomFrame
            → top.bottomFrame → parent.bottomFrame
        若 bottomFrame 存在：
            若該框架標記了「本次交易已回復」：
                清除該標記並直接結束本函式（不顯示任何訊息）
            若該框架提供 showNotifyMsg：
                呼叫 showNotifyMsg({ returnCode: msgs[0][5], returnMessage: msgs[0][0] })
                // 固定只送第 0 筆
    攔截所有錯誤並忽略

    alertMessages()                                // 此步驟不在上述錯誤攔截範圍內

alertMessages()：
    alertMsg ← ''
    對 msgs 中的每一筆 m：
        若 m[6]（異常原因）為空字串：
            若 m[5]（回傳碼）不等於 "0" 且 不等於 "99"：
                alertMsg ← alertMsg + "訊息說明:\n" + m[0] + "\n"
                若 m[1]（錯誤編號）為真值：
                    alertMsg ← alertMsg + "\n錯誤編號：\n" + m[1]
        否則：
            若 m[6] 不為空 或 m[2]（程式 ID）不為空：
                alertMsg ← alertMsg + "異常原因:" + m[6] + "\n"
                alertMsg ← alertMsg + "\n程式ID:" + m[2] + "\n\n"
    若 alertMsg 不為空字串：
        若全域同時存在 WIUtil 與 jQuery：以 WIUtil 的訊息視窗顯示 alertMsg
        否則：以瀏覽器原生提示視窗顯示 alertMsg
```
**累加方式**：`alertMsg` 為**每次重算**（函式進入時重設為空字串），非增量維護。
**邊界條件**：
- **`msgs` 長度為 0**（本畫面正常開啟時的情形）：`msgs[0][5]` 存取 `undefined` 的屬性會拋出型別錯誤，被外層錯誤攔截吞掉，底部訊息框不會被更新；隨後 `alertMessages()` 因迴圈不執行而 `alertMsg` 為空，不顯示彈窗。最終效果是「什麼都不做」，但路徑是經由例外達成的。`[DEFECT]`（見 §15-26）
- **回傳碼為 `"0"` 或 `"99"`**：不加入彈窗文字（`99` 的設計意圖為保留在底部訊息框）。
- **同時有多筆訊息**：全部串接後只彈一次；但送往底部訊息框的固定只有第 0 筆。
- **訊息含單引號、雙引號或反斜線**：於伺服器輸出 JS 字串字面量時未逸出，會破壞腳本。`[DEFECT]`（見 §15-25）

### 8.5 複製內容稽核（來自 `header.jsp`，僅在 `PD_CTRL='Y'` 時存在）

**目的**：在資安管制功能下，記錄使用者從畫面複製的內容。
**輸入**：使用者當下的選取範圍、全域變數 `lastfpcsRecordText`。
**輸出**：一次 GET 稽核回寫（見 §6.3）。
**虛擬碼**：
```
當 document.body 上發生 copy 事件時：
    selected ← 取得選取文字
        // 若目前焦點在 textarea：取該 textarea 的 selectionStart..selectionEnd 子字串
        // 否則：取視窗選取範圍的文字
        // 舊版瀏覽器：取 document.selection 建立的範圍文字
    selected ← 將 selected 中連續的空白字元（含換行）折疊為單一空格
    record ← selected

    若 record 長度 > 0 且 record 不等於 lastfpcsRecordText：
        設定一個 60000 毫秒的一次性計時器：時間到時將 lastfpcsRecordText 重設為 ""
        lastfpcsRecordText ← record
        若 record 長度 > 5000：
            record ← record 的前 4997 個字元 + "..."
        依序取代：% → %25，# → %23，& → %26，空格 → %20，+ → %2B，? → %3F，= → %3D
        建立一個 img 元素，將其來源設為稽核位址，帶上：
            COPY_CONTENT = record
            FUNC_ID      = 伺服器渲染時嵌入的功能代號（本畫面為 DSC80106）
            COPY_LENGTH  = selected 的長度（取代與裁切之前的長度）
            TS           = 前端當下時間戳
```
**邊界條件**：
- **選取為空**：不回寫。
- **連續複製相同內容**：60 秒內只回寫一次；60 秒後計時器重設旗標，相同內容會再次回寫。
- **超過 5000 字元**：裁為 4997 字元加 `...`；但 `COPY_LENGTH` 仍回報裁切前的真實長度。
- **計時器**：每次成功回寫都新增一個 60 秒計時器，不會取消先前的計時器；連續複製不同內容時會累積多個計時器，任一到期都會把旗標清成空字串。
- **取代順序**：`%` 先取代，避免把後續產生的百分比編碼再次編碼；此順序正確。
- **未取代的字元**（如中文、`/`、`'`、`"`）直接進入查詢字串，不做百分比編碼。
