## 1. 用途

保險公司內部人員以「身分證字號／統一編號」查詢某一當事人在壽險公會通報系統中的投保通報資料。畫面同時提供三層資訊：該當事人所有通報保單的保障金額與保費彙整（含本公司與同業）、逐筆通報明細，以及單筆資料的人工修正入口。

使用者為核保／契約管理人員；在核保或契約作業流程中，用來確認被保人或要保人在業界的累計保額、判斷是否超過風險承擔上限，並在公會通報資料有誤時進行修改或刪除，或即時向公會重新取回資料。

## 6. 服務契約

## 8. 演算法規格

### 8.1 selectItem — 將選取列帶入編輯區

**目的**：把明細表中被點選那一列的資料，複製到編輯區的顯示元素與送出元素，並啟用編輯操作。
**輸入**：`detailRadio`（被點擊的 radio 元素），其 `value` 為該列的 0 起算索引。
**輸出**：無回傳值；副作用為 DOM 變更。
**虛擬碼**：

```
函式 selectItem(detailRadio):
    i ← detailRadio.value                      // 0 起算的列索引，字串

    // (1) 純送出欄位：只寫 hidden
    設 hidden「TBL_NAME」.值 ← hidden「TBL_NAME」+i 的值

    // (2) 成對欄位（共 21 組）：同時寫顯示 span 與送出 hidden，兩者取同一來源
    對於 F 屬於 {INSR_TYPE, CMNY_CODE, I_ID, I_BIRTHDAY, POLICY_NO,
                POLICY_CAT, POLICY_DUTY, PROD_KIND, STATUS, LST_CHG_DATE,
                MAIN_POLICY_NO, ISSUE_DATE, ISSUE_TIME, LPS_DATE, LPS_TIME,
                SIGN_DATE, PREM, PAY_FREQ, PAY_PERIOD, LST_CHG_TIME, SER_NO}:
        設 span「F_text」.文字 ← hidden「F」+i 的值
        設 hidden「F」.值     ← hidden「F」+i 的值

    // (3) 第 22 組：顯示與送出取自「不同」來源  ← 刻意如此，原始碼有註解
    設 span「UPDATE_TIME_text」.文字 ← hidden「INPUT_TIME」+i 的值
    設 hidden「UPDATE_TIME」.值      ← hidden「UPDATE_TIME」+i 的值

    // (4) 可編輯金額欄 19 個：來源 id 多一個底線
    對於 n 由 1 到 19:
        設 輸入框「PAY_AMTn」.值 ← hidden「PAY_AMTn_」+i 的值

    // (5) 其他可編輯欄
    對於 F 屬於 {BROKTYPE, A_NAME, A_ID, A_BIRTHDAY, RELATION, I_GENDER, PAY_TYPE}:
        設 輸入元件「F」.值 ← hidden「F」+i 的值

    // (6) 純顯示欄：取「說明」而非代碼（PROD_CODE 例外，取代碼）
    設 span「OIU_IND」.文字   ← hidden「OIU_IND_DESC」+i 的值
    設 span「SALE_CHNL」.文字 ← hidden「SALE_CHNL_DESC」+i 的值
    設 span「PROD_CODE」.文字 ← hidden「PROD_CODE」+i 的值

    // (7) 狀態切換
    啟用 按鈕「editBtn」、「deleteBtn」、「cleanAllBtn」
    顯示 區塊「editArea」

    呼叫 parseEUDC()                            // 行為 [UNKNOWN]，見 §14-7
```

**基準點與初值來源**：所有值的**唯一來源是該列的 hidden 元素**，這些 hidden 由伺服器在前次回應渲染時嵌入（§3.C）。編輯區的欄位沒有任何伺服器初值（除失效的 `TBL_NAME`）。索引基準是 **radio 的 `value`＝`${status.index}`，0 起算**，不是「序號」欄顯示的 `${status.count}`（1 起算）。

**邊界條件**：

- 零筆資料：不存在任何 radio，本函式永不執行，編輯區永遠隱藏。
- 來源 hidden 的值為空字串：顯示與送出皆為空字串，**不做任何補值或預設**。
- 若任一來源 hidden 不存在（例如伺服器某次回應少渲染一個欄位），`$(...)` 回傳 null，讀取 `.value` 會**擲出例外並中斷整個函式**——已執行的賦值保留、其後的不執行、編輯區不會顯示、按鈕不會啟用。此路徑**沒有 `try/catch`**。
- 型別轉換：完全沒有。所有值以字串搬移，金額欄不檢查是否為數字。
- 反覆點選不同列：整批覆寫，不合併、不提示未存檔。

### 8.2 doCleanAll — 清空編輯區

**目的**：放棄目前的選取與編輯，把編輯區還原為初始狀態。
**輸入**：無。
**輸出**：無回傳值；副作用為 DOM 變更。
**虛擬碼**：

```
函式 doCleanAll():
    設 hidden「TBL_NAME」.值 ← ""
    對於 F 屬於 {與 §8.1 步驟 (2) 相同的 21 組，加上 UPDATE_TIME}:
        設 span「F_text」.文字 ← ""
        設 hidden「F」.值     ← ""
    對於 n 由 1 到 19:
        設 輸入框「PAY_AMTn」.值 ← ""
    對於 F 屬於 {BROKTYPE, A_NAME, A_ID, A_BIRTHDAY, RELATION, I_GENDER, PAY_TYPE}:
        設 輸入元件「F」.值 ← ""
    對於 F 屬於 {OIU_IND, SALE_CHNL, PROD_CODE}:
        設 span「F」.文字 ← ""

    取得 所有 name 為「item」的元素集合 ele
    對於 j 由 0 到 ele.長度-1:
        設 ele[j].checked ← false

    停用 按鈕「editBtn」、「deleteBtn」、「cleanAllBtn」
    隱藏 區塊「editArea」
```

**基準點與初值來源**：清空的目標值一律是**空字串**，不是伺服器初值、也不是上一次選取的值。

**邊界條件**：

- 零筆資料：`getElementsByName("item")` 回傳空集合，迴圈不執行，其餘動作照常（本函式只在按鈕啟用時才可能被呼叫，而按鈕啟用必經 `selectItem`）。
- `I_GENDER` 與 `PAY_TYPE` 是 `<select>`，設 `value = ""` 時**沒有 value 為空字串的 option** → 瀏覽器行為為「無任何選項被選取」（`selectedIndex` 變 -1）。此時若送出，該參數會送出空值或不送出，**依瀏覽器而異**。
- **不清除**查詢條件區的 `inputId`、`IS_RETURN`、`role`、`status`（見 §15-29）。
- **不重設**排序箭頭與明細列順序。

### 8.4 sortTable1 — 切換排序方向並委派排序

**目的**：切換欄標題的箭頭符號，並把排序請求轉給外部排序模組。
**輸入**：`col`（欄索引，0 起算）、`tableToSort`（表格元素，呼叫端傳入裸識別字 `rtnTable`）、`rowToSort`（字串 `'rtnID'`）、`dataType`（固定 `0`）、`idName`（箭頭 span 的 id）。
**輸出**：無回傳值。
**虛擬碼**：

```
函式 sortTable1(col, tableToSort, rowToSort, dataType, idName):
    aObj ← 取得元素(idName)
    sort_type ← 0                       // 先指派數字 0

    若 aObj.文字 = '▼':
        aObj.文字  ← '▲'
        sort_type ← '0'                 // 再指派字串 '0'（型別不一致）
    否則:
        aObj.文字  ← '▼'
        sort_type ← '1'

    sortCol ← -1                        // 隱含全域，重設外部模組的欄位狀態

    呼叫 sortTable(col, tableToSort, rowToSort, dataType, sort_type,
                   false, '#F0F8FF', '#FAFBE1')
```

**基準點與初值來源**：排序方向的**唯一狀態載體是箭頭 span 的文字**（初值 `▼`），不是任何 JavaScript 變數。`sortCol` 每次都重設為 `-1`，表示外部模組不記憶上一次排序的欄位。

**邊界條件**：

- 箭頭文字若既不是 `▼` 也不是 `▲`（不會發生於現況，但若外部模組改寫則可能），走 else 分支設為 `▼`、`sort_type='1'`。
- **同時只有被點擊那一欄的箭頭會改變**；其他欄的箭頭仍停在上一次的狀態，畫面上可能出現多欄同時顯示 `▲`，但實際只有最後一次點擊的欄有效。
- 零筆／一筆資料：仍會切換箭頭並呼叫 `sortTable`，結果 `[UNKNOWN]`。

### 8.5 fix / stat — 標題列定位

**目的**：讓絕對定位的標題列 `bar1` 在捲動或縮放時維持在畫面上緣。
**輸入**：無（讀取全域 DOM 與捲動量）。
**輸出**：無回傳值。
**虛擬碼**：

```
函式 fix():
    若 存在元素('bar1'):
        a ← document.body.scrollTop − 元素('bar1').offsetHeight + 30
        bar1.style.top ← a                  // 無單位；bar1 為隱含全域
    否則:
        呼叫 stat()

函式 stat():                                 // 現況永不執行，見下方邊界條件
    若 document.bar1 ≠ null:
        a ← pageYOffset + window.innerHeight − document.bar1.document.height − 15
        document.bar1.top ← a
    設定計時器(呼叫 stat, 2 毫秒)             // 無終止條件
```

**基準點與初值來源**：`fix()` 的基準是 `document.body.scrollTop`（捲動量）減去標題列高度再加固定偏移 `30`。

**邊界條件**：

- `bar1` 是**無條件輸出的靜態元素**（第 374 行），因此 `document.getElementById('bar1')` 恆非 null → **`stat()` 永不被呼叫**（`[DEAD-CODE]`，見 §15-18）。
- `stat()` 若被呼叫，其 `setTimeout(...,2)` 沒有任何終止條件，會以每 2 毫秒的頻率無限遞迴排程。
- `bar1.style.top ← a` 指派的是**不帶單位的數字**，CSS 會忽略（除非值為 0）→ 標題列實際上不移動（`[DEFECT]`，見 §15-17）。
- `document.body.scrollTop` 在標準模式下多數瀏覽器恆為 0（`[DEFECT]`，見 §15-19）。本檔的 DOCTYPE 為 HTML 4.01 Transitional（第 5 行），且該 DOCTYPE 前已有 `header.jsp` 的輸出（見 §15-1），實際渲染模式 `[UNKNOWN]`。
- 原始碼第 36 行註解：「firefox 3 已經不支援 window.onresize，暫不處理」。

### 8.6 doASyncCheck — 取回公會資料前的身分證檢核

**目的**：在向公會即時取資料前，先請後端檢核輸入的身分證字號／統一編號；不合規則時要使用者確認是否仍要繼續。
**輸入**：`inputId` 欄位的當下值。
**輸出**：無回傳值；副作用為發出非同步請求，並可能整頁送出。
**虛擬碼**：

```
函式 doASyncCheck():
    若 valid.validate() 為假:               // 驗證規則見 §9
        直接返回（不做任何事、不送出）

    inputId ← 欄位「inputId」的當下值

    發出非同步請求(位址 = ⟨dispatcher⟩ + "/AFY1_0100/doASyncCheckId",
                  參數 = { inputId: inputId }):
        成功時(回應 resp):
            若 resp.isIdError = 'Y':
                訊息 ← "輸入值 " + inputId +
                       " 不符身份證/統一證號檢核規則，請確認，是否要繼續作業?"
                若 使用者在確認對話框按下「確定」:
                    呼叫 doASync()          // 整頁送出
                // 按「取消」則不做任何事
            否則:
                呼叫 doASync()              // 整頁送出
        // 沒有失敗分支
```

**基準點與初值來源**：`inputId` 取自**欄位當下值**（不是伺服器渲染的初值），因此使用者按 F8 前修改輸入框的內容會生效。

**邊界條件**：

- `inputId` 為空：`valid.validate()` 應回傳假並中止（依 §9 的 required 規則），但實際的驗證與訊息行為依賴 `validation.js` `[UNKNOWN]`。
- 請求失敗、逾時、伺服器錯誤：**無任何處理，畫面無反應**（見 §6.4）。
- `resp.isIdError` 為 `undefined`（回應缺欄位）：走 else 分支 → **直接送出**，等同視為檢核通過。
- 比較是嚴格的字面值 `'Y'`；小寫 `'y'` 或其他值都視為通過。
- 若 `${isAllow}` 為假，`btn_async` 不存在，本函式只能由熱鍵 F8 觸發，而 F8 註冊的目標元素亦不存在（見 §10）。

### 8.8 displayMessage / alertMessages — 伺服器訊息顯示

（來源：`/html/CM/msgDisplayer.jsp` 第 103–171 行，本檔在 `initApp()` 呼叫。）

**目的**：把伺服器透過訊息物件回傳的執行結果顯示給使用者。
**輸入**：`msgs` 陣列（伺服器渲染時展開，每筆 7 欄，見 §7.1）。
**輸出**：無回傳值；副作用為更新下方訊息框與跳出警示。
**虛擬碼**：

```
函式 displayMessage():
    嘗試:
        bottomFrame ← 依序尋找 top.leftFrame.bottomFrame、parent.leftFrame.bottomFrame、
                              top.bottomFrame、parent.bottomFrame（第一個找到者）
        若 找到 bottomFrame:
            若 bottomFrame 上有「本次交易已回滾」旗標:
                清除該旗標並直接返回（不顯示任何訊息）
            若 bottomFrame 有 showNotifyMsg 函式:
                以 msgs[0] 的「回傳碼」與「訊息說明」呼叫之
    遇到任何例外: 忽略

    呼叫 alertMessages()

函式 alertMessages():
    alertMsg ← ""
    對於 每一筆訊息 m 屬於 msgs:
        若 m[6]（異常原因）為空字串:
            若 m[5]（回傳碼）≠ "0" 且 ≠ "99":       // 0=正常、99=只寫入下方訊息框
                alertMsg ← alertMsg + "訊息說明:\n" + m[0] + "\n"
                若 m[1]（錯誤編號）非空:
                    alertMsg ← alertMsg + "\n錯誤編號：\n" + m[1]
        否則:
            若 m[6] 非空 或 m[2]（程式 ID）非空:
                alertMsg ← alertMsg + "異常原因:" + m[6] + "\n"
                alertMsg ← alertMsg + "\n程式ID:" + m[2] + "\n\n"

    若 alertMsg ≠ "":
        若 WIUtil 與 jQuery 皆存在: 以 WIUtil 顯示 alertMsg
        否則:                        以瀏覽器警示視窗顯示 alertMsg
```

**基準點與初值來源**：`msgs` 由伺服器渲染；累加器 `alertMsg` **每次呼叫重新從空字串開始累加**（非增量維護）。

**邊界條件**：

- `msgs` 為零筆：`displayMessage()` 中 `msgs[0]` 會是 `undefined`，讀 `[5]` 擲例外 → 被外層 `try/catch` 吞掉；`alertMessages()` 迴圈不執行，`alertMsg` 為空 → 不跳警示。
- 回傳碼 `"0"`（正常）與 `"99"`（只寫入下方訊息框）**不跳警示**。
- 本頁**不在框架中時**：找不到 `bottomFrame`，`displayMessage()` 的前半段被 `try/catch` 吞掉，只剩警示視窗。
- 本檔對這些訊息**不做任何處理**：不判斷成功或失敗、不據此改變畫面狀態。
