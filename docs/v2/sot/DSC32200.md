## 1. 用途

本畫面供收費作業人員將「以郵政劃撥方式收到、但尚未沖銷到特定帳務」的款項登錄為人工暫收帳。
使用者輸入單位代號／貸款帳號與暫收原因後，在明細表中逐列登錄劃撥日期與劃撥金額（劃撥帳號固定），系統即時累計合計金額，按「確認」將整批資料送交後端建帳。
建帳過程中後端會回傳洗錢防制檢核結果；若檢核未過或需補登記錄，畫面會導向洗錢防制檢核（AIL0_1300）或可疑交易檢核（AIL1_1000）的彈出視窗。
使用者為壽險收費／帳務作業單位人員，此畫面位於「繳款方式」功能群組之下（第 279 行 `PageUI.createPageWithAllBodySubElement('DSC32200', '繳款方式', '劃撥入人工帳')`）。

### 5.1 顯示欄位與送出欄位不一致者

1. **`TRANS_NO`（劃撥帳號）**：顯示端由 `createInputElement('TRANS_NO','00041496','account','劃撥帳號')`（第 304 行）產生，第二參數是寫死常數，**完全忽略 TableUI 傳入的 `value`**；送出端則取 record 的 `TRANS_NO`。兩者在正常路徑同為 `00041496`，但在 `doDelete` 全刪分支（第 244 行）record 被設為 `'${TRANS_NO}'`，此時畫面仍顯示 `00041496`，送出的卻是伺服器渲染值。

## 8. 演算法規格

### 8.1 新增明細列（doInsert）

**目的**：在明細表末端追加一筆空白劃撥資料。
**輸入**：`#LOAN_ID` 目前值、`grid` 現有全部 record、模組變數 `count`、伺服器渲染值 `${TRANS_DATE}`。
**輸出**：明細表重繪；`count` 遞增 1。
**虛擬碼**：
```
若 LOAN_ID 為空字串或假值：
    彈出訊息「單位代號/貸款帳號不可空白!!」
    中止（不新增）

dataList ← 明細表全部 record（含使用者已編輯的內容）
count ← count + 1

新列 ← {
    TRANS_SERNO : count,
    TRANS_NO    : "00041496",          // 寫死常數，非伺服器值
    TRANS_DATE  : 伺服器渲染的 ${TRANS_DATE},   // 頁面載入時即固定
    TRANS_AMT   : 0,                   // 數值 0，非字串
    REMARK      : "",
    preCheck    : "Y"                  // 預設勾選
}
dataList 末端加入 新列

以 dataList 重新載入明細表（全表重繪，每列重新執行 render）
執行 autoFormatToNumber()              // 行為未知
```
**邊界條件**：
- `#LOAN_ID` 為空：中止，不新增。
- `#LOAN_ID` 僅含空白字元：`$F` 回傳非空字串，檢核**通過**，仍會新增。
- `count` 為 `undefined`（初始化尚未完成即點擊）：`undefined + 1` → `NaN`，新列序號成為 `NaN`。實務上按鈕事件在 `initApp` 中綁定，此路徑不可達。
- `${TRANS_SERNO}` 渲染為非數值時：第 329 行 `count=${TRANS_SERNO};` 為語法錯誤，整段程式不執行。
- 明細表列數超過 `pageSize`（20）：換頁行為與 `getAllRecords()` 是否跨頁 `[UNKNOWN]`。
- **新增動作不做任何欄位驗證**，可在既有列日期／金額尚未填妥時連續新增。
- **新增動作不更新 `#TOTAL_AMT`**（新列金額為 0，合計理應不變；但若 `Temp_AMT` 已因 §8.3 的邊界條件變成 `NaN`，此處也不會修正）。

### 8.2 刪除選取列與序號重編（doDelete）

**目的**：移除勾選的明細列，並把剩餘列的序號重新編為連號。
**輸入**：`grid.getCheckedRecord()`（勾選列）、`grid.getAllRecords()`（全部列）、模組變數 `newSerNO`、伺服器渲染值 `${TRANS_NO}`、`${TRANS_DATE}`。
**輸出**：明細表重繪；`Temp_AMT` 重算；`count` 更新；`#TOTAL_AMT` 更新。
**基準點與初值來源（依 §D2）**：序號重編的起點是**模組變數 `newSerNO`**，其值為頁面載入時伺服器渲染的 `${TRANS_SERNO}`，或最近一次 `confirm` 成功時後端回傳的 `resp.TRANS_SERNO`。**不是 1，也不是重編前的最小序號。**
**虛擬碼**：
```
selectData ← 明細表中勾選的 record 陣列
若 selectData 筆數 = 0：
    彈出訊息「請勾選欲刪除的電匯資料」
    中止

initSERNO ← newSerNO                  // 重編基準，全程不變
records   ← 明細表全部 record
newDataList ← 空陣列

// 分支 A：全部列都被勾選
若 selectData 筆數 = records 筆數：
    Temp_AMT ← 0                      // 直接歸零，非重算
    count    ← newSerNO
    newDataList ← [ {
        TRANS_SERNO : newSerNO,
        TRANS_NO    : 伺服器渲染的 ${TRANS_NO},   // 注意：此處用伺服器值
        TRANS_DATE  : 伺服器渲染的 ${TRANS_DATE},
        TRANS_AMT   : 0,
        REMARK      : "",
        preCheck    : "Y"
    } ]

// 分支 B：部分列被勾選
否則：
    counter  ← 1
    Temp_AMT ← 0                      // 歸零後每次重算，非增量維護
    對 records 中每一筆 item（依原始順序）：
        del_flag ← false
        對 selectData 中每一筆 delItem：
            若 item.TRANS_NO = delItem.TRANS_NO 且
               item.TRANS_SERNO = delItem.TRANS_SERNO：
                del_flag ← true
                跳出內層迴圈
        若 del_flag = false：           // 此列保留
            item.TRANS_SERNO ← parseInt(initSERNO) + counter
            newDataList 末端加入 item
            Temp_AMT ← Temp_AMT + parseInt(item.TRANS_AMT, 10)
            counter  ← counter + 1
    count ← parseInt(initSERNO) + counter - 1

以 newDataList 重新載入明細表
#TOTAL_AMT ← 千分位格式化(Temp_AMT)
previousRecord ← null                  // 未宣告的全域變數，無其他讀寫
```
**邊界條件**：
- 零筆勾選：中止並提示，不變更任何狀態。
- 全選（分支 A）：表格不會變成空的，而是重建為一列空白資料；序號回到 `newSerNO`（不是 `newSerNO+1`），**與分支 B 保留第一列時得到的 `newSerNO+1` 不同**。
- 分支 A 使用 `${TRANS_NO}`，分支 B 與其他所有路徑使用 `"00041496"`（見 §15-7）。
- 比對鍵是 `TRANS_NO` + `TRANS_SERNO` 的組合。因為 `TRANS_NO` 全表同值，實際等同只比 `TRANS_SERNO`；若序號重複則會一次刪掉多列。
- `item.TRANS_AMT` 為空字串或非數字時：`parseInt('', 10)` → `NaN`，`Temp_AMT` 自此成為 `NaN`，`#TOTAL_AMT` 顯示 `CSRUtil.$fmt(NaN,'#,###')` 的結果 `[UNKNOWN]`。
- `initSERNO` 為非數值字串時：`parseInt` 回傳 `NaN`，所有重編序號成為 `NaN`。
- 跨頁（列數 > `pageSize` 20）時 `getCheckedRecord()` 與 `getAllRecords()` 是否涵蓋非當頁列 `[UNKNOWN]`。
- 本演算法**不呼叫後端**，刪除只發生在前端資料結構上。

### 8.3 合計金額增量維護（劃撥金額輸入框 blur）

**目的**：使用者改動單列金額時，同步更新合計顯示。
**輸入**：`event.target.value`（使用者輸入，可能含千分位逗號）、該列 record 的 `TRANS_AMT` 舊值、模組變數 `Temp_AMT`。
**輸出**：`Temp_AMT` 更新；`#TOTAL_AMT` 重新顯示；輸入框重新格式化；record 更新。
**方式**：**增量維護**（不是每次重算）。
**虛擬碼**：
```
tr      ← 此輸入框所在的資料列
dataObj ← tr.dataObj，取不到則以 tr 的 sn 屬性向明細表查第一筆 record
new_value ← 輸入框目前字串值            // 可能含逗號，如 "1,234"

若 此欄的 colkey = "TRANS_AMT"：
    Temp_AMT ← Temp_AMT − dataObj.TRANS_AMT + parseInt(去除所有逗號(new_value))
    #TOTAL_AMT ← 千分位格式化(Temp_AMT)

// 下面兩步對所有 number 型欄位都執行
若 new_value 為真值 或 new_value 嚴格等於數值 0：
    輸入框值 ← 千分位格式化(new_value)
否則：
    輸入框值 ← ""
dataObj[colkey] ← 去除所有逗號(new_value)    // 存字串，不是數值
```
**邊界條件**：
- `new_value` 為空字串：`parseInt('')` → `NaN` → `Temp_AMT` 變成 `NaN`，且之後任何增量運算都無法讓它變回數值（只有 §8.2 的刪除或頁面重載能重置）。
- `dataObj.TRANS_AMT` 在首次編輯前是數值 `0`，之後是字串；減法運算會自動轉型，兩種情形都可運算。但字串為空時 `Temp_AMT − ''` → 減 0，與預期的減去舊值不同。
- `new_value` 恆為字串，故 `new_value === 0` **永遠為 false**；該條件是死條件，實際只靠 `new_value` 的真假值判斷（空字串 → 清空輸入框）。
- `parseInt` 未指定基數（第 130 行），以 `0` 開頭的輸入在舊版直譯器可能被當八進位。§8.2 的同類呼叫則有帶 `10`，兩處寫法不一致。
- 使用者輸入負號、小數點或非數字：`parseInt` 只取可解析的前綴，`#TOTAL_AMT` 與輸入框顯示可能不一致；無任何阻擋。
- `dataObj` 兩種取得路徑都失敗時：對 `undefined` 取屬性會拋例外，事件處理中止。

### 8.4 明細列輸入框產生（createInputElement）

**目的**：依欄位型別產生明細表格內的輸入元素。
**輸入**：`colkey`（資料鍵，同時作為 DOM id）、`value`（該列該欄的值）、`type`（`'date'` / `'number'` / 其他）、`col_nm`（中文欄名）。
**輸出**：一個 DOM 元素（`date` 回傳 `<span>`，其餘回傳 `<input>`）。
**虛擬碼**：
```
theID ← colkey                        // 同一欄的每一列都得到相同 id

若 type = "date"：
    td ← 新 <span>
    input ← 新 <input>，屬性：
        class     = "textBox2 validate-ROCDate required TRANS_DATE_CHK"
        id        = theID              // 逐列重複
        name      = theID + "_input"   // 逐列重複
        datatype  = "ROCdate"
        size      = 9
        maxlength = 7
        fieldName = col_nm
    input 的值 ← Date.toInputROC(value 或 "", "")      // 轉民國年顯示
    對 input 註冊 change：
        找到所在資料列的 record
        record[colkey] ← toY2K(輸入值 或 "")            // 轉西元年存檔
    clan ← 新 <img src=<%=imageBase%>/CM/calendar.gif alt="Date">
    對 clan 註冊 click：呼叫 getCalendarFor(input)
    td 依序插入 input、clan
    回傳 td

否則若 type = "number"：
    input ← 新 <input>，屬性：
        class     = "textBox2 required TRANS_AMT_NOT0"
        id        = theID
        name      = theID + "_input"
        type      = "text"             // 非 number 型別
        datatype  = "number"
        pattern   = "#,###"
        size      = 15
        maxLength = 15                 // 大小寫與 date 分支不一致
        fieldName = col_nm
    若 value 為真值 或 value 嚴格等於 0：
        input 的值 ← 千分位格式化(value)
    否則：
        input 的值 ← ""
    對 input 註冊 blur：執行 §8.3
    回傳 input

否則（其他型別，本檔僅 "account" 走此分支）：
    input ← 新 <input>，屬性：
        class     = "textBox2 required"
        id        = theID
        name      = theID + "_input"
        type      = "text"
        size      = 10
        fieldName = col_nm
        readonly  = true
    input 的值 ← value                 // 直接指派，不做真假判斷
    回傳 input
```
**邊界條件**：
- `type` 傳入 `'account'`（第 304 行）落入第三分支，`'account'` 這個字串在程式中沒有任何比對邏輯，等同「預設分支」。
- 第三分支呼叫時傳入的 `value` 是寫死的 `'00041496'`（第 304 行），**TableUI 提供的 `value` 參數被丟棄**。
- `value` 為 `undefined` 時：第三分支會把輸入框設成字串 `"undefined"`（無真假判斷）；`date` 與 `number` 分支則有 `|| ''` 或真假判斷保護。
- 同一欄的每一列 id 相同 → `$('TRANS_AMT')` 一類的取用只會取到第一列（本檔未如此取用，但 `validation.js` 的行為 `[UNKNOWN]`），見 §15-1。
- `date` 分支的 `change` 事件在使用者以鍵盤輸入後失焦時觸發；若月曆元件以程式設定 `input.value` 而未派發 `change`，record 不會更新 `[UNKNOWN]`。
- `number` 分支被註解掉的原始寫法 `//input.value = value || '';` 保留在第 104 行，旁註「原寫法chrome會有問題」——該註解位在 `date` 分支，說明的是 `date` 分支改用 `Date.toInputROC` 的原因。

### 8.5 確認送出與送出後重置（doConfirm）

**目的**：把整批明細送交後端建帳，並依回應決定導頁或重置畫面。
**輸入**：`#BALC_REASON` 值、`valid1` 驗證結果、`grid` 全部 record、`#LOAN_ID`、`#TOTAL_AMT` 的 `innerHTML`。
**輸出**：後端請求；依回應更新明細表與 `count`／`newSerNO`，或開啟外部檢核視窗。
**虛擬碼**：
```
若 BALC_REASON 值 == 17：                             // 入追償款（寬鬆相等，字串 "17" 亦成立）
    詢問「確定暫收原因為入追償款，且已經輸入貸款貸號？」

transList ← 明細表全部 record

    若 回應.ERR_MSG 為真值：                           // 洗錢防制檢核未過
        彈出 回應.ERR_MSG
        parms ← { LINK_TO:回應.LINK_TO,
                  QUERY_ID:回應.QUERY_ID,
                  CURRENT_DATE:回應.CURRENT_DATE }
        執行 §8.6 導頁
        // 明細表、Temp_AMT、count、newSerNO 一概不動
    否則：                                             // 建帳成功
        若 回應.TIPS_MSG 為真值：彈出 回應.TIPS_MSG
        rtnList ← [ { TRANS_SERNO : 回應.TRANS_SERNO,
                      TRANS_NO    : "00041496",
                      TRANS_DATE  : 回應.TRANS_DATE,
                      TRANS_AMT   : 0,

                      preCheck    : "Y" } ]
```

**輸出**：完整可操作的畫面。

### 8.8 後端訊息顯示（displayMessage，由 msgDisplayer.jsp 引入）

**目的**：把伺服器帶回的訊息顯示在框架下方訊息列，並以彈窗顯示錯誤。
**輸入**：伺服器渲染的 `msgs` 陣列。每筆 7 欄，依序為：`[0]` 訊息說明、`[1]` 訊息編號、`[2]` 系統／程式 ID、`[3]` 類型、`[4]` URL、`[5]` 回傳碼、`[6]` 異常內容。原始換行（`\r\n`、`\n`、`\r`）在伺服器端先轉為 `<br>`，前端再還原為 `\n`。
**輸出**：下方訊息列更新與／或彈窗。
**虛擬碼**：
```
displayMessage():
    嘗試：
        bottomFrame ← 依序尋找
            top.frames['leftFrame'].frames['bottomFrame']
            → parent.frames['leftFrame'].frames['bottomFrame']
            → top.frames['bottomFrame']
            → parent.frames['bottomFrame']
        若找到 bottomFrame：
            若該框架帶有 txHasRollbackPage 旗標：
                清除該旗標並「直接返回」（不顯示任何訊息，也不執行 alertMessages）
            取得該框架的 showNotifyMsg 函式
            若是函式：以 { returnCode: msgs[0][5], returnMessage: msgs[0][0] } 呼叫
                                                  // 只顯示第一筆
    例外：完全吞掉，不做任何處理

    alertMessages()

alertMessages():
    alertMsg ← ""
    對 msgs 每一筆 m：
        若 m[6]（異常內容）為空字串：
            若 m[5]（回傳碼）不是 "0" 也不是 "99"：       // 0=正常，99=只寫訊息列不彈窗
                alertMsg += "訊息說明:\n" + m[0] + "\n"
                若 m[1]（訊息編號）非空：
                    alertMsg += "\n錯誤編號：\n" + m[1]
        否則：
            若 m[6] 非空 或 m[2] 非空：
                alertMsg += "異常原因:" + m[6] + "\n"
                alertMsg += "\n程式ID:" + m[2] + "\n\n"

```
**邊界條件**：
- `msgs` 長度為 0（伺服器無訊息，見 §3.1 最後一列）：`msgs[0][5]` 對 `undefined` 取索引會拋例外；該行在 try 區塊內，例外被吞掉，接著仍執行 `alertMessages()`——但此時 `showNotifyMsg` **不會被呼叫**，下方訊息列不會被更新。

- 回傳碼為 `"99"`：只寫訊息列、不彈窗（原始註解明載）。
- 回傳碼為 `"0"`：兩者皆不做。
- 多筆訊息：訊息列只顯示第一筆，彈窗則把符合條件的全部串接後一次顯示。
- 本畫面在 `initApp` 最後一步呼叫 `displayMessage()`（第 339 行），註解「初始頁面alert訊息用」。

**目的**：記錄使用者從頁面複製走的內容。

- 驗證器建立參數為 `new Validation("form", { focusOnError:true, immediate:false, mode:'validator' })`（第 69 行）。

  - `immediate:false` → **不做即時／失焦驗證**，只在呼叫 `validate()` 時檢核。

- `doConfirm` 在 `valid1.validate()` 回傳 false 時 `return`，**中止後續動作**（不送出請求、不改變任何狀態）。
- 錯誤訊息的呈現位置與樣式 `[UNKNOWN]`（由 validation.js 決定）。
- 上表後四條（alert 與 confirm 型）不經驗證框架，失敗時不聚焦任何欄位，只中止該按鈕的流程。
- **沒有任何規則會在欄位失焦當下即時檢核。**
