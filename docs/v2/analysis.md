## 1. 摘要

### 1.1 總體判定

三份 SoT 的**準確度異常地高**。我以抽樣覆核方式驗證了 60 餘項可機械核對的斷言（行號、樣式使用次數、欄位數、儲存格數、引入檔行號、EL 清單），**僅發現 5 項事實錯誤**，且全部是行號或計數的小幅偏差，沒有任何一項會誤導再工程。主要問題不在「寫錯」，而在**三份文件之間的嚴謹度不一致**，以及**少數依賴範圍外資訊的推論被寫成肯定句**。

## 5. 對規則的改進建議

### 5.1 現行 rules.md 沒有規則涵蓋的問題

| # | 問題 | 對應發現 | 建議新增規則 |
|---|---|---|---|
| R-1 | **標準標籤庫／平台元件的邊界行為未被要求記錄。** rules.md D4 只要求「每個演算法都要寫邊界條件」，而 `<fmt:formatNumber>`、`<c:if>` 的 EL 真假值轉換這類**宣告式標籤**不被視為「演算法」，於是 88 個儲存格的空值渲染行為整批漏掉 | G-01（high） | **新增 B5**：凡是由 JSP 標籤庫或平台元件產生輸出的位置（`fmt:*`、`c:*`、自訂標籤），§3 渲染契約須在「型別/格式」欄同時記錄 **正常值** 與 **空值／null／不可解析值** 三種輸入下的輸出結果；不可知時標 `[UNKNOWN]` |
| R-2 | **內嵌事件處理函式的「預設動作」未被要求記錄。** rules.md 沒有任何一條要求記錄 `<a onclick>` 是否阻止預設導覽。§10 事件表只要求「事件／目標／處理」三欄 | G-03（high） | **新增 D7**：內嵌於 HTML 屬性的事件處理，須註明**是否阻止預設行為**（`return false`／`preventDefault`／兩者皆無）及其可觀察後果（捲動位置、瀏覽歷程、表單送出） |
| R-3 | **沒有任何規則要求三份 SoT 之間彼此一致。** 同一個 `header.jsp` 在三份中被登記了 8／4／0 項缺陷；同一個「scriptlet 與 EL 混用」在一份是 `[DEFECT]`、另兩份不登記；同一個「jQuery 未載入」在一份標 `[ASSUMPTION]`、另一份寫「必定」 | G-05、G-11、G-12、O2-3 | **新增 L 節「跨文件一致性」**：<br>**L1** 共用引入檔（`header.jsp`、`msgDisplayer.jsp`）的行為與缺陷抽成**一份獨立的共用元件 SoT**，各畫面 SoT 只寫「引用 + 本畫面的實際條件值（`PD_CTRL`、`IS_WATERMARK`）+ 本畫面受影響的具體行為」。<br>**L2** 同一種缺陷型態在多份 SoT 出現時，登記與否的判準須一致；判準寫在共用規則而非各文件內。<br>**L3** 同一命題在不同 SoT 中的標註強度（肯定句／`[ASSUMPTION]`／`[UNKNOWN]`）須一致 |
| R-4 | **沒有規則規範「行數／計數口徑」與「查證範圍宣告」。** DSC32200 用 `wc -l`（383）、DSC80106 用實際行數（241），兩套口徑；查證範圍的宣告三份各行其是——只有 DSC80106 有獨立章節，AFY10100 僅在 §16 帶過一次，DSC32200 全文 0 次 | O3-3、O4-1 | **新增 A5**：SoT 開頭須宣告**行號與行數的計數口徑**（是否計入無結尾換行的最後一行）。<br>**新增 E5**：SoT 結尾須有「查證範圍」章節，明列**已完整讀取**與**明確排除**的檔案；§15 判定「經查後無」時，須在該章節指出查證方式。（實測三份中只有 DSC80106.md 具備此章節，DSC32200.md 全文未出現「查證範圍」字樣） |

### 5.2 有規則但沒擋住的問題，以及規則為何失效

| # | 規則 | 沒擋住的發現 | 規則為何失效 |
|---|---|---|---|
| F-1 | **A3「不知道就標 `[UNKNOWN]`，不得推測後以肯定句陳述。若必須推論，標 `[ASSUMPTION]` 並寫出推論依據」** | O2-1、O2-2、O2-3、O2-5、O2-7、O2-8、O2-9（7 項） | A3 只說了「**不知道**就標未知」，但這 7 項的共通結構是：**作者知道一半**——他驗證了本檔範圍內的前提（`rtnMap` 在本檔內只由 forEach 宣告、本檔沒有載入 jQuery、本檔的 select 只由 selectItem 顯示），然後把「本檔範圍內為真」直接當成「執行期為真」。A3 沒有提供**判斷「這個結論是否越出可讀範圍」的操作程序**，作者自然覺得自己是在陳述已驗證的事實。<br>**修補**：把 A3 改成可執行的檢查——「凡是結論句含『恆』『必定』『永不』『完全』『實際上』等絕對語氣的，須逐一回答：**支撐這個結論的每一個前提，是否都在本輪可讀範圍內？** 只要有一個前提落在範圍外，該句一律降為 `[ASSUMPTION]` 並把該前提寫進 §14。」並把這五個詞列進 §K 檢查清單的關鍵字掃描 |
| F-2 | **A3 後半「必須推論時標 `[ASSUMPTION]` 並寫出推論依據」** | 同上，特別是三份間的密度落差（1.24／2.60／0.20 每百行） | 規則沒有給**密度預期**，也沒有要求「範圍外依賴愈多、`[ASSUMPTION]` 應愈多」。AFY10100 的 §13 列了 12 項範圍外相依，§14 列了 27 項未知，`[ASSUMPTION]` 卻只有 4 個——形式上每條規則都遵守了，實質上推論被藏進肯定句。<br>**修補**：§K 增加自查項「§14 的每一個未知項，是否都檢查過本文有無依賴它的肯定句？」——把未知清單當成**反查索引**使用，而不只是輸出清單 |
| F-3 | **§K 檢查清單全部是「有沒有寫」，沒有一條是「寫得對不對」** | O3-1～O3-5（5 項事實錯誤，全部是行號／計數偏差） | §K 的 17 個項目全是存在性檢查（「每一個 `${…}` 都有對應列」「每個外部腳本都有列」）。這類檢查已經奏效——§3 覆蓋率 266/266、標籤文字零誤差、樣式使用次數全部精確——但**沒有任何一條要求回頭驗證已寫下的行號與計數**。五項錯誤全部集中在「作者憑印象補上的行號區間與個數」。<br>**修補**：§K 增加「每一個引用的行號區間，都回原始碼 `sed -n 'N,Mp'` 確認過一次」「每一個出現在文中的計數（『共 N 處』『N 個空格』），都以機械方式數過一次」兩項；並要求在文件結尾附上所用的核對指令 |
| F-4 | **G2「下列一律登記：重複的 DOM 識別碼／用字不一致／空元素…」與 G4「用字不一致視為缺陷」** | G-04（漏 18 個重複 id）、G-07（`innerText`/`textContent`）、G-09（漏 BALC_REASON 無 name）、G-10（script type 大小寫）、G-14（漏兩支未使用腳本） | G2／G4 是**開放式清單**（「一律登記」但不說如何窮舉），作者只能靠肉眼掃描。結果是每份 SoT 都登記了一批，但每份都漏了幾個同類的。這五項的共通點是**都可以機械列舉**。<br>**修補**：§K 增加「機械列舉清單」——重複 id（`grep -o 'id="[^"]*"' \| sort \| uniq -d`，且**須另行檢查迴圈內的所有 id**，它們在執行期必然重複）、未使用的載入項（比對 `<script src>` 與全檔函式呼叫）、無 `name` 的表單元素、同一屬性的大小寫變體。把「一律登記」改成「依下列指令逐項列舉後登記」 |
| F-5 | **F1「所有硬編碼字面值進 §11.1」** | O1-1、O1-2（§11.1 與 §4.3 重複）與 G-08（DSC32200 漏列腳本路徑） | F1 是本輪**同時造成過度與遺漏**的規則：因為「所有」的範圍無界，作者要嘛全抄（DSC80106 把 `'10%'` 的 19 個行號都列了，與 §4.3 重複）、要嘛憑感覺取捨（DSC32200 漏了 10 支腳本路徑）。規則沒有給分類，執行就沒有下限也沒有上限。<br>**修補**：即前述 F4 新規則——把 §11.1 限定為「承載業務或設定語意的字面值」，並明列必收類別（服務代號、動作名、參數名、代碼值、閾值、逾時、鍵碼、外部資源路徑、畫面代號與標題），版面屬性明確排除 |
| F-6 | **D4「每個演算法都要寫邊界條件：空值、零筆、全選、型別轉換失敗」** | G-02（`selectItem` 漏 select 值域不符） | D4 給了四個範例邊界，但**沒有涵蓋「寫入目標本身有值域限制」這一類**（`<select>`、`<input type=radio>`、有 `maxlength` 的欄位）。同一份 SoT 在 `doCleanAll` 寫出了這個邊界、在 `selectItem` 漏掉，顯示作者是靠直覺而非清單。<br>**修補**：D4 的邊界條件範例增列「**寫入目標的值域限制**：寫入 `<select>` 的值不在選項中、寫入超過 `maxlength`、寫入非預期型別」，並在 §K 增加「同一個元素在不同演算法中的邊界條件是否一致？」 |
