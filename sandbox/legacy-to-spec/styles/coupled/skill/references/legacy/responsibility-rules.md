# JSP 前後端耦合拆解

## 先盤點，不按語法分層

JSP 的 scriptlet、EL、自訂 tag、include、JavaScript 和 hidden 值可能同時承載呈現、業務、情境與資料交換。先逐段記錄觸發、資料來源、條件、執行順序、輸出、狀態及副作用，給每項 `LOGIC-*`，再分責任；「在 JSP」或「在 JavaScript」都不能單獨決定歸屬。

讀 [權威分工](../api/authority.md) 和 [API 轉寫規則](../api/writing-rules.md)。來源只證明 legacy 在該條件下的行為；後端產物才證明目標後端已承接什麼。

## 責任分類

| 類型 | 判斷依據 | 前端規格保留 | 目標處理 |
| --- | --- | --- | --- |
| 呈現與操作體驗 | 排版、文字顯示、焦點、展開、欄位連動等可見行為 | UI／ST／FLOW 及前端證據 | 前端責任；不能因由服務端渲染就全數丟掉 |
| 已知資料呈現轉換 | 從既有資料按明確規則排成畫面，不新增業務決策 | DATA→UI 轉換與格式；不得暗改精度、值或語意 | 可歸前端呈現；wire schema 仍依後端 |
| 業務運算／檢核 | 計算、資格、狀態決策、資料有效性、涉及業務結果 | 觸發、輸入與結果語意；前端既有提示另保留 | 交給後端承接，前端檢核不能取代後端保障 |
| 資料或外部副作用 | 資料讀寫、交易、檔案、郵件、批次、外部模組 | BOUND、順序、必要資料與可見結果 | 已有 API 則映射；否則 HANDOFF |
| 受信任情境 | 登入者、單位、權限、服務端 session、工作日期或環境設定 | 情境語意、可見權限效果、合法交接方式 | 由後端已確認機制提供／判定；不能改成前端可任填欄位 |
| 混合或不明 | 同一片段跨上述責任，或工具契約不足 | 已知部分與缺口分開 | 拆成多個 LOGIC 但保留原順序；未知列 TODO |

日期、代碼名稱、金額與預設值可能是呈現，也可能是業務決策；要依來源用途和後端契約判定。服務端常數若屬系統情境，不直接烘進 prototype 作為固定產品值。

## 初始化與渲染

將首次進入所需的資料取得與可見渲染分別盤點，保留兩者先後及初始狀態。後端已提供初始化 API 時，核對是否覆蓋所有舊的值、選項與旗標；名稱叫 prompt 不代表資料已完整。

若只有原本 JSP 直接取得的值，建立其語意 DATA、資料來源 E 及 HANDOFF。不要假定需新增一支「初始化 API」；可以由後端選擇適當承接方式，前端只記錄需求與缺口。必要資料尚未知時不可把初始化改成空畫面或本機常數後宣告等價。

## 對應到後端

每項 LOGIC 記錄前端證據、責任、後端承接產物 E、對應 API／BOUND、缺口與處理結論。已承接必須核對輸入、條件、順序、輸出和副作用，不只比對方法名。

若一段原有交易被拆成數個 API，不能假定客戶端依序呼叫仍保持原交易原子性。回滾、失敗中止、部分成功、重送等有證據的需求保留給後端；缺保證就列 HANDOFF／TODO，不用前端補償邏輯代替。

混合片段拆分後，保留資料相依和原執行順序。前端清空欄位、後端運算與重新顯示若交錯，需逐步映射，不把所有前端步驟移到最後。位置改變會影響可見結果時列差距，不能視為純粹整理。

## 尚未承接的移交契約

使用 [backend-handoff.md](../../templates/integration/backend-handoff.md) 產生 `artifacts/integration/<scope-id>/backend-handoff.md`；只在存在實際缺口時建立。

HANDOFF 描述已證實的舊責任、觸發、輸入與受信任情境、條件、順序、輸出、異常和副作用，連到相關 FLOW／BR／DATA／AC。它是後端待承接的需求，尚不是可呼叫 API；不指定新端點、框架、資料表設計或後端實作方法。未知部分連 TODO，不補造。

追蹤文件管理 LOGIC 分類、待辦、承接狀態與驗證。後端正式產物可定位地承接後，才能把對應 HANDOFF 映射到 API、補上投影並執行所需驗證；移交檔案本身完成不足以關閉 TODO。

prototype 只展示已確認的可見狀態及本機資料，不執行後端運算或資料副作用。展示數值若只是情境資料就標示合成，不以本機算法宣稱已完成後端承接。
