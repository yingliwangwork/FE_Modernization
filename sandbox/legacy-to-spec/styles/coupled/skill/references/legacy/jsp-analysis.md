# 來源解析參考：JSP 與相依資源

本文件是目前的來源技術 profile；它不指定翻新後的技術棧。HTML prototype 是審閱載體，不是實作選型。

## 範圍與讀取

每輪只有一個 root JSP。先檢查其編碼宣告、實際位元組編碼與行尾；以可讀副本分析必要的轉碼，不修改 legacy 原件。記錄原始版本、行號基準與轉碼方式。JSP 的靜態文字未必等於最終畫面，條件、include 與 tag 輸出皆須追查。
每份依賴的編碼、實際行數與行尾都需個別驗證，不沿用根入口或鄰近檔案的紀錄。使用 [source_inventory.py](../../scripts/source_inventory.py) 或等效工具取得雜湊、原始位元組行數及候選編碼的嚴格解碼結果，例如 `python3 <skill>/scripts/source_inventory.py <檔案> --candidate utf-8 --candidate cp950`。解碼成功仍須核對宣告與可讀語意；兩者皆失敗時保留未確認，不用替換字元或「另一個編碼應該可讀」補造結論。記錄工具實際輸出及其行號基準。

依本頁行為追查 include、taglib、自訂 tag、共用 script、樣式、資源字串與直接呼叫的 handler。將每項依賴登錄到 tracking；不可取得的依賴建立具體 TODO。另一 JSP 的頁面內部不因連結而納入本輪 scope。

共用依賴需從本頁的實際呼叫點追到相關條件分支與回應者，而非只列元件名稱。特別分開入口初始化訊息、非同步成功／拒絕訊息、底部訊息區、原生警示與自訂訊息視窗的呈現條件、原文與順序；取得其中一種不能代表其他種類已覆蓋。實際部署會選哪個分支未知時，將選用條件列 TODO，仍記錄來源中已知的各分支反應、文案、焦點／阻斷行為及可見副作用。

共用請求鏈還需盤點註冊的所有回呼與例外處理者，包含 onException 等診斷分支、觸發來源、組裝訊息與阻斷。success／failure／complete 名称盤點不代表例外分支已覆蓋。

訊息元件需核對輸入正規化（空字串、null、未定義、換行）、重複內容、累積順序、尺寸增長／保持、重定位、清除與焦點。以連續多次呼叫及邊界值核對生命週期，不只核對單次非空訊息。

樣式按本頁可匹配選擇器、權重、引入順序與繼承核對最後生效值；同名 class 的第一個規則不等於最終樣式。保留適用的 :root 等較高權重規則，不從孤立 CSS 宣告推斷呈現。

## 事件作用範圍與時間關係

逐個追查事件的註冊對象（window、body、特定元件）、註冊／解除時機、傳播階段、預設動作與阻斷。全域政策不能為展示方便縮到產品容器；審閱工具若需豁免，必須標示其測試性質且保留原有產品／頁面範圍。

計時器需記錄每次建立、是否取消／重設、作用狀態與到期副作用。多次獨立計時器可能交錯影響同一狀態；來源未取消舊計時器時，不自行加入 debounce 或重新起算。以時間序列核對，不能只核對最終文字。

共用元件的指標互動也需盤點，包括標題拖曳的按下、移動、放開、座標偏移、拖曳框與視窗可見性，以及監聽解除／重建。只盤點確認按鈕和鍵盤關閉不足以代表元件完整。
事件監聽以每次註冊實例追蹤身分與解除對象；自我解除的回呼不能改為引用後來被覆寫的共用變數。驗證關閉後重開、不同關閉方式與首個事件的組合，不只驗證第一次顯示。

## 觀察點與轉譯

| 來源觀察點 | 要取得的事實 | 規格表達 |
| --- | --- | --- |
| directive、靜態／動態 include、自訂 tag | 實際引入條件、可見區塊、依賴角色 | 畫面構成及條件；解析細節留在證據 |
| scriptlet、expression、EL、條件 tag | 入口資料、預設值、渲染分支、角色判斷 | 前置條件、狀態、規則與分支 |
| form、hidden、action、method、submit 攔截 | 傳遞資料、動作選擇、已知交接 | 邊界輸入輸出；來源 URL 與欄位符號留在 tracking |
| JavaScript 事件、onload、timer、callback | 觸發、順序、guard、欄位連動、回應處理 | FLOW、BR、TR；不可只列函式名稱 |
| 非同步呼叫、回傳代碼、錯誤處理 | 已實作成功／空值／失敗分支與資料副作用 | 各條件的結果與後置狀態 |
| link、redirect、frame、popup、download | 目的、傳遞資料、視窗／頁面交接方式 | BOUND 及使用者所見導覽結果 |
| CSS、表格版面、圖示、tab order、焦點處理 | 資訊層級、對齊、可見性、尺寸、焦點順序 | SCR、UI、狀態差異與操作體驗 |
| 訊息資源、alert、confirm、例外區塊 | 文案、觸發條件、取消／確認結果 | MSG 與對應分支 |
| 權限 tag、session 檢查、角色旗標 | 顯示／可操作條件與可見拒絕行為 | 角色規則；不推導未取得的服務端授權 |

對使用者可辨識的 URL、檔案格式與代碼，依 [證據規則](../../guides/evidence.md) 判斷是否屬可觀察契約；不可一律刪除。

## 後端邊界

若只看到送出的參數，規格可以確認送出條件與資料，但不能確認儲存結果、交易一致性、服務端驗證或權限。目標契約先依 [權威分工](../api/authority.md) 查找指定後端產物；適用實作與觀察可協助核對，差異需列衝突，不能自行替代選定基準。不可取得時逐項建立 TODO，停止該未知分支的行為生成。

看到多個送出動作時分別盤點。hidden 欄位可能承載使用者不可見但影響流程的狀態，不能因不可見就忽略；也不能把所有 hidden 欄位直接做成可見 UI。

JSP 內直接執行後端行為時，讀 [耦合拆解方法](responsibility-rules.md) 逐段建立 LOGIC。只有呈現責任保留為前端行為；業務、存取、副作用與受信任情境需映射後端承接，缺少時建立 HANDOFF／TODO。語法掃描需包含 scriptlet、EL、自訂 tag、include 的間接呼叫、session 和 response 寫入，不只搜尋 form 或 script。

遇到 eBAF 自訂工具時，依 [後端設計參考](../api/backend-profile.md) 按需查閱工具契約。工具名稱及文件中的示例不能證明本 JSP 使用該業務規則；仍需記錄實際呼叫參數、情境與本頁結果。

## UI/UX 證據強度

只有原始碼時，可描述其明確定義的結構、樣式與事件；不得聲稱已驗證執行畫面的像素一致性、實際效能或瀏覽器差異。沒有樣式或圖片時不得自行指定品牌色、圖示意義、響應式斷點或動畫。沒有鍵盤、焦點與返回行為證據時明列未知，不套用常見 UX。

已觀察的舊缺陷保留證據；是否修正另列變更提案與確認結果。prototype 如採用了新行為，必須能追溯至已確認變更，不能隱藏於版面整理中。
