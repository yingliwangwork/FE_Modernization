# HTML prototype 的視覺契約

## 定位

prototype 用於審閱系統畫面與互動。至少一份，可因同一入口的不同畫面、彈窗或展示狀態拆分。正式規格保持技術中立；HTML、CSS 與展示腳本只存在於 prototype 和本參考文件。

[prototype.html](../../templates/design/prototype.html) 是可離線開啟的空骨架。其虛線區域與審閱工具沒有來源證據，不能當作任何系統 UI 的樣式、區塊數量或需求；產出實際 prototype 時必須依證據替換。範本沒有業務資料，也沒有預設成功、錯誤或載入狀態。

## 元件樣式交付

有樣式設計的元件依 [樣式規則](style-spec.md) 同時產出 DESIGN.md 與 prototype 載入的 CSS。scope 版面、繼承字型、共用元件與變體均需盤點；來源未確認的設計保留 TODO。審閱骨架的 CSS 只服務審閱工具，不成為產品預設。

## 一致性映射

產出的文件在 root 標示 `data-scope-id`、`data-screen-id`、`data-state-id`。真實可見元素以 `data-ui-id` 對應規格，觸發動作以 `data-flow-id` 對應流程；有可見狀態切換時，其目前狀態屬性同步更新。審閱工具不使用這些產品 ID。

規格原型索引逐列列出檔案、SCR、ST、FLOW／TR、展示資料與限制。若狀態由同一檔案切換，需記錄進入該狀態的可重現操作；若互動無法展示，可用不同 HTML 表示已知前後狀態，並在索引註明只能視覺檢查。

## 生成規則

- 以來源證明的標籤、順序、欄位、群組、必填、禁用、顯示條件、結果欄位、文字與導覽方式重建。未知部分在審閱層標示 `TODO-*`，不合成推測的功能。
- 已知互動使用本機展示腳本或本地頁面連結；不呼叫 legacy API，不寫入真實資料，不送出表單到未知目的地。未知的回應不能用假成功取代，應停在已知邊界並由審閱層指出缺口。
- 合成資料只用來顯示已確認的資料形狀、長度與邊界案例，標示為展示資料，不作為業務規則的證據；不得複製真實個資、密碼或 token。
- 系統可見訊息應依 MSG 原文展示。尚未取得的文案不能用「成功」「失敗」等通用文字假扮系統訊息。
- 有共用元件時以 `data-component-id` 對應 CMP，保留本頁有證據的用法與差異。API wire 欄位映射依介接文件，不能用展示資料補造後端 schema。未承接的 HANDOFF 只標缺口，不在展示腳本重製後端業務運算或受信任狀態。
- 審閱工具、狀態選擇器與說明置於獨立區域，標示「審閱工具」並可隱藏，不混入使用者操作流程。展示資料的註記保留在審閱層／規格索引。
- 審閱層注入外部回應時，不因其控制按鈕的事件傳播而增加、清除或重排產品反應。保留真實產品事件範圍與原有先後；在實際瀏覽器驗證注入時序，不能只靠最小 DOM 替身宣稱一致。
- CSS 和小量腳本採本地或內嵌資源；不依賴遠端 CDN，開啟時不應對外連線。外部導覽在本機展示交接，不真的開啟業務系統。
- 已證實的鍵盤、焦點、取消、重複動作及返回行為都需保留。模板工具本身使用語意化控制與可見焦點；這不代表 legacy 頁面已具備該能力。

prototype 保留有證據的事件範圍、計時器建立／取消與交錯反應，以及拖曳等手勢的中間狀態。不可擅自加入重新計時、把全頁政策縮到區塊、或省略已知手勢來簡化展示；無法執行的互動明列限制及驗證缺口。

已知元件多次呼叫及邊界輸入應有可重現展示方法；需要時在審閱層提供合成訊息輸入／型別選擇。元件空值回退、累積內容與尺寸策略都要與來源一致，不能只硬編一個成功示例來代表整個契約。

## 核對方式

逐一比較規格的可見元素和畫面狀態，檢查所有已知 FLOW／TR 的前後結果。確認每個可操作元素都能執行已證實的展示行為；無法展示的部分明列於索引和 tracking。

在瀏覽器實際開啟，測試索引中的進入步驟、互動、鍵盤操作及有證據的尺寸。檢查語法、控制台錯誤與意外連線；記錄檢查結果和截圖於 tracking。未取得 legacy 執行畫面時只能核對來源結構，不能宣告視覺等價。瀏覽器無法使用時如實記錄未執行的視覺驗證。
核對審閱層的層疊與尺寸是否遮住產品控制，尤其是等待時的回應注入與訊息視窗的確認操作。調整審閱層使兩者可操作，產品本身的已知層級与行為仍按來源保留；不能用強制點擊或直接呼叫關閉函式掩蓋被遮擋的控制。
