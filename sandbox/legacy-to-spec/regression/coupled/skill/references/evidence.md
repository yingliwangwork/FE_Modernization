# 證據、語意與缺口

## 主張分類

| 分類 | 可寫入的內容 | 必要依據 |
| --- | --- | --- |
| 已證實 | 在指定條件下發生的行為或明確規則 | 可定位來源、可重現觀察或確認紀錄；逐筆引用 `E-*` |
| 未知 | 哪個條件／反應／意圖無法確認，影響哪些契約 | `TODO-*` 指向 tracking 的具體待查問題 |
| 衝突 | 各來源互相矛盾之處，不選一方作為既定契約 | 各方 `E-*` 與裁決用 `TODO-*` |
| 不適用 | 本範圍內可確認不涉及的能力 | 檢查範圍、理由及 `E-*`；找不到程式碼本身不足以證明 |

這些分類不是信心分數。不得把推測加上「可能」「應該」後放進正式行為。追查線索可寫在 TODO，必須標為待驗證且不得被 prototype 模擬為既有行為。

來源的可取得性、可呼叫性與系統的存在／部署狀態分開判定。「未提供可呼叫環境」只能寫成該測試／交付缺少環境；未有部署證據時寫「部署狀態未確認」，不得改寫為「未部署」。同理，未取得相依文件或未列在契約中，不等於能力不存在或已停用。只有能定位的否定證據才支撐這類否定主張。

## 證據要求

證據必須符合 [權威分工](authority.md)：前端來源支撐 UI／互動，後端產物支撐目標 API／業務能力。JSP 的後端片段可以證明 legacy 行為，但不能單憑該片段宣告目標端點已存在。登錄前端與後端各自的版本、來源性質與適用範圍。

- 原始碼：相對路徑、來源版本／內容雜湊、原始行號或穩定符號、精簡摘錄、支撐哪一項主張及不能支撐什麼。轉碼後另記行號對應，保留原件。
- 執行觀察：環境、時間、角色、前置資料、操作步驟、實際結果、可取得的截圖或錄影路徑。單一角色或資料的觀察不能推廣成所有情境。
- 人工確認／既有文件：可定位的紀錄、版本／日期、確認者角色、確認的適用範圍。與原始碼不同時列為衝突或已確認變更。
- 註解與名稱是線索；若註解陳述意圖，可引用為「文件所述意圖」，不能因此斷言執行結果。原始碼證據與執行觀察各保留，不預設誰永遠優先。
- 每個功能性主張必須可追溯。表格一列可共用證據，但一列包含多項不同依據時分列；不可用章首一個引用涵蓋整份文件。

不得因為畫面有送出按鈕就推導資料一定寫入；不得因呼叫名含驗證就推導驗證條件；不得因前端隱藏按鈕就推導服務端授權成立。

## 技術中立的轉譯

前端系統設計規格用業務語意或可觀察語意命名，legacy 來源符號映射留在 tracking。資料契約使用文字、整數、小數、日期、布林、集合等概念型別，描述方向、必填條件、單位、格式、允許值及空值意義；不指定傳輸協定、端點、資料庫、函式或框架。API 文件獨立轉寫後端精確傳輸契約，依 [API 規則](integration-contract.md) 保留 wire 名稱、格式與代碼，不將其語意轉譯成新欄位。

例如，若來源證明一個欄位變更後另一欄位被清空，描述「收到欄位 A 變更事件後，系統清空欄位 B」，並引用來源。不要把實作函式名稱寫成需求。若後續選項如何取得未有證據，只對該部分建立未知，不連已知的清空行為一起抹除。

使用者可見的文字、代碼、下載格式、輸入格式或跳轉目的若本身是契約，應保留；技術中立不代表刪掉使用者可辨識的資訊。正式文件的證據連結可指向追蹤登錄表，但不內嵌來源語法。

## 領域參考按需建立

需要專案詞彙或領域規則時，使用 `references/domains/<domain>.md`，或引用專案已存在的權威文件。只在實際翻新取得材料後新增；目前不預填任何業務知識。

每份領域 reference 至少記錄：術語／規則、適用範圍、權威來源與版本、已確認或衝突狀態。只載入本輪必要部分，並將實際採用的條目登錄為 `E-*`。領域 reference 本身不能憑空替代來源。特定技術的新解析規則放入來源 reference，不寫回 SKILL.md。

## 穩定 ID

ID 在同一 scope 內唯一，跨 scope 以 `<scope-id>/<ID>` 引用；不因文件排序而改號。

| 前綴 | 代表 |
| --- | --- |
| `E-*` | 證據 |
| `INT-*` / `ACT-*` | 意圖／角色或觸發者 |
| `SCR-*` / `UI-*` / `ST-*` | 畫面／可見元素／系統或畫面狀態 |
| `CMP-*` | 前端共用元件契約與本頁使用方式 |
| `DATA-*` / `BR-*` / `MSG-*` | 資料語意／規則／訊息 |
| `FLOW-*` / `TR-*` / `BOUND-*` | 流程／分支或轉移／邊界互動 |
| `AC-*` | 驗收案例定義 |
| `API-*` / `HANDOFF-*` | 後端契約的消費投影／待後端承接的有證據需求（介接文件） |
| `LOGIC-*` | 來源中的混合邏輯盤點與責任分類（僅追蹤） |
| `TODO-*` / `V-*` / `CHANGE-*` | 待辦／驗證執行／增量紀錄（僅追蹤） |
