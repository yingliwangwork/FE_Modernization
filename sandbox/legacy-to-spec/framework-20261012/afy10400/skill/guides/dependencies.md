# 依賴契約重用與處理決策

本文件管理 DEP 的查找、適用性、使用者決策與局部缺口；工作順序依 [workflow](workflow.md)。

## 依賴盤點

在已建立的 plan 中盤點 include、script、樣式、圖片、tag、訊息、共用元件、跨頁入口與服務交換。新發現的間接依賴增補計劃；尚未分析的項目保留待盤點。

每筆依賴分配 DEP-ID，記錄來源、引入條件、與入口的關係、本輪必須取得的行為、影響的畫面／流程／資料／API／驗證項目、可取得性與停止邊界。尚未分配契約 ID 時先以具體位置描述，後續補上 ID。

## 先查既有契約

在使用者指定的規格目錄、交付索引及已提供材料中，以資源確切路徑、元件／scope ID 查找；記錄搜尋範圍與結果。搜尋無結果只表示該範圍內未找到，不宣稱整個系統沒有規格。

候選規格必須核對：對應的來源與版本、責任權威、所需行為與條件分支、適用情境、缺口以及相依契約。只有涵蓋所需部分才可重用；名稱相同、檔案存在或文件標為完成都不足以證明適用。

- 已有且適用：直接引用契約路徑／章節／ID、版本或雜湊、本頁使用條件；不複製改寫整份共用規格。可將本頁用法映射為 CMP／FLOW，既有定義仍由原契約維護。
- 部分適用：引用有證據的部分，剩餘部分作為未轉換／版本不符缺口處理。
- 未找到、無法取得或版本／權威不符：登錄具體缺口，不能退回讀完整來源並自動翻新來繞過使用者決策。可做足以說明影響的有限盤點，詳細契約生成要等決策。

## 未轉換依賴的對話與兩種處理

先完成可供決策的 plan 記錄，再在對話中逐項或成組告知：DEP-ID、資源位置、查找結果、未確認內容、對根 JSP 的影響、可獨立繼續部分。提出「先翻新」或「延後」選擇。問題依執行環境可用的對話方式送出；不可只在檔案寫待確認而不告知使用者。
成組告知時核對該決策關聯的每筆 DEP／TODO，讓對話、plan 任務範圍及 tracking 缺口一致。未向使用者說明的缺口不能暗中納入該組決策授權；後續新發現的影響需補充告知並保留待決部分。

例：「DEP-03 的共用訊息資源在指定索引中尚無適用規格，影響送出後的錯誤回饋與焦點；欄位盤點可繼續。要先建立此依賴的規格，還是本輪延後並保留 TODO？」實際使用須填確切資源與影響，不照抄例子。

1. **先翻新**：記錄使用者決策／既有授權的來源、適用資源和範圍。在 plan 排列依賴工作及阻塞關係；先完成必要依賴規格，再引用到根入口。共用資源可建立自己的契約，另一個 JSP 的完整行為另開 scope，不增加本輪根入口。不可取得的部分仍列 TODO，不因選了先翻新就填猜測。
2. **延後**：記錄決策來源，建立 TODO 與後續任務，列需要取得的資料、下一步、完成條件、影響與重新驗證範圍。在設計的每個受影響 FLOW／CMP／UI／BOUND／DATA／ST 等位置寫明 `TODO-ID：哪部分未完成` 並連到 tracking 的缺口；只有總索引不足。tracking 的 TODO 連回 plan 任務與決策；plan 記錄後續順序和依賴。prototype 的審閱層在對應區域揭露缺口，不捏造缺失互動。

驗證時把每筆缺口的所有受影響 ID 展開為位置表，逐列記錄該 ID 所在章節的實際 TODO 錨點連結，以及對應 plan 任務／決策。包含資料字典與狀態表，不能只核對流程和總缺口索引。位置表是核對紀錄；需回讀實際文件確認連結存在，不能把預期連結填入表當作已完成。
影響範圍從依賴實際作用與缺失內容推導後回查來源，不以人工選中的位置表自稱全覆蓋。全域／繼承樣式需核對適用的 UI 定義；共用條件可在實際共用契約位置標記 TODO，再由使用位置引用該契約，避免複製整段缺口說明。已確認事實與尚未建立的共用契約分開標示，不將所有內容都視為未知。

尚未回覆時維持「待決」，只能繼續不依賴該資源的工作。等待時間不是授權；不能擅自將待決改成延後。若使用者已明確決定相同依賴／範圍，沿用紀錄，不重問。

## 續作與驗證

更新共用契約時保留原版本引用，列出受影響的消費 scope／ID 與重新驗證任務。僅於新契約提供缺失行為及必要驗證證據後關閉 TODO；文件出現或任務完成本身不是關閉依據。對延後或待決依賴，不宣告其行為完整。
