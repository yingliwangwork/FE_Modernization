# Legacy to Spec：翻新哲學

## Goals

- 產出可理解、可追溯、可驗證的技術中立系統契約與視覺成果，保留已有證據的意圖和體驗。
- 先建立翻新計劃，再辨識外部資源、依賴與影響；重用適用契約，依使用者決策逐步補齊缺口。
- 分離系統設計、跨邊界契約與翻新執行紀錄，讓每次小範圍交付可持續維護。

## Constraints

- 每輪只有一個入口來源；依賴分析不自動授權擴大翻新範圍。
- 不以推測補造行為、意圖或外部能力；未建立、未知與衝突保留可定位的缺口。
- 本文件只定義翻新哲學。來源技術、領域知識、程序與交付細節放在按需引用的參考文件。

## Rules

翻新的成果是可理解、可追溯、可驗證的系統契約。以系統在特定情境下接收什麼事件、做出什麼反應，以及使用者能觀察到什麼結果，取代對既有實作語法的重述。

### 證據先於描述

只有直接來源、可重現觀察或可定位的確認紀錄能支撐行為主張。命名、慣例與經驗只能協助尋找證據，不能代替證據。缺少依據時保留問題與其影響，不生成看似完整的答案；衝突時保留各方證據，不自行裁決。

### 保留意圖與體驗

保留資訊層級、操作順序、狀態變化、回饋、限制、資料副作用及跨邊界互動。業務意圖必須有依據；只看見操作時就只描述操作，不擴張成未確認的目的。原有缺陷和改良提案分開記錄，不藉翻新悄悄改變契約。
事件的作用範圍、時間關係與生命週期也是契約；不能因展示方便改變觸發對象、取消時機或中間狀態。

### 權威依責任分配

畫面、互動與共用呈現以前端來源為權威；服務能力、交換契約與業務處理以後端產物為權威。跨邊界需求要同時保留兩端依據，不能由一端的期待補造另一端的能力。指定適用版本並分清既有事實、設計承諾與展示替身；有矛盾時揭露差距，不任意改寫任一端的契約。

### 耦合必須拆責任

同一來源承載多種責任時，先還原事件、資料來源、判斷、順序與副作用，再逐項界定責任。執行位置不等於責任歸屬。呈現留給前端，業務決策與受信任狀態交由後端；尚未被後端承接的行為形成有證據的移交需求，不在前端重製，也不假定已有可用邊界。

### 以觸發與結果組織契約

每個流程說明觸發者、事件、前置狀態、條件、系統反應、可見結果及後置狀態。使用者、系統生命週期與外部回應皆可能觸發流程。不同條件產生不同結果時，保留各分支；未知分支不得偽裝成成功路徑。某個情境是否成立未知時，仍保留各已證實分支的反應，不能整體省略。

### 先計劃，再沿依賴推進

先留下入口、初始邊界與任務計劃，再分析依賴並更新影響。每項任務記錄依賴、影響範圍與驗證條件。已有適用規格直接引用其版本和使用範圍；尚未轉換的依賴納入計劃，告知使用者缺口與影響，由使用者決定先翻新或延後。沿用已有明確授權，不將沉默當作決策。延後時在受影響契約位置保留 TODO，並連到計劃中的後續處理。

### 小範圍累積

每次以一個入口來源檔案建立可控邊界。依賴可以支撐理解，但不能自動擴張為另一個翻新單位。尚未建立、未能取得或未確認的部分留在獨立追蹤紀錄中，後續以穩定識別碼補充，不覆蓋既有證據與決策。

### 契約與執行分離

設計規格描述系統應有的可觀察行為；翻新追蹤描述分析、待辦、驗證與進度。兩者透過識別碼互相連結，不把工作排程寫成系統需求。有樣式設計的元件同時交付可追溯的樣式契約與視覺成果使用的樣式，兩者逐項核對；客製化不改變證據要求或權威歸屬。視覺原型與文字契約共用同一套行為事實；展示用資料與審閱工具不能變成新需求。

### 完整性必須能被檢查

完整性以已界定範圍的證據、流程、狀態、互動與驗證覆蓋判定，不以篇幅判定。沒有發現不等於不存在；尚未取得的資訊不等於不適用。必要行為仍有缺口時，交付可追蹤的部分成果並說明限制，不宣告完整。

## Workflow

依 [工作方法](guides/workflow.md) 先建立計劃、確認依賴決策，再形成契約與視覺成果，最後驗證並更新追蹤。續作沿用識別碼與既有決策，回查來源和依賴版本變動；流程細節由參考文件定義。

### 按需引用

- 開始或續作翻新：讀 [工作方法](guides/workflow.md)，選用範本並建立邊界。
- 查找既有依賴契約或遇到未轉換資源：讀 [依賴與決策](guides/dependencies.md)，先核對可重用性與影響。
- 選定各類權威與參考既有轉換設計：讀 [權威分工](references/api/authority.md)；相關來源背景見 [後端設計參考](references/api/backend-profile.md)。
- 轉寫服務交換契約：讀 [介接契約方法](references/api/writing-rules.md)。
- 單一來源混合多種責任：讀 [耦合拆解方法](references/legacy/responsibility-rules.md)。
- 判斷事實、未知、衝突及術語：讀 [證據規則](guides/evidence.md)。領域知識的引用條件也定義於此。
- 分析特定來源形式：讀 [來源解析參考](references/legacy/jsp-analysis.md)。技術細節只存在於參考文件。
- 選用或客製可重用範本：讀 [範本客製化](guides/customization.md)，實際成果另存。
- 建立或核對視覺成果：讀 [視覺契約](references/ui/writing-rules.md)；有元件樣式時讀 [樣式契約](references/ui/style-spec.md)。
- 判斷是否可交付：讀 [驗收規則](guides/acceptance.md)。

## Output Format

依工作方法選用範本，分別維護系統行為規格、視覺成果、適用的跨邊界契約、翻新計劃與執行追蹤。以穩定識別碼和有效連結連接成果；缺口標記放在對應契約位置，處理進度與決策留在計劃及追蹤。

## Evaluation Criteria

- 已界定的行為、分支、互動與副作用有證據及驗證去向。
- 任務依賴與影響可追蹤；重用契約適用，未轉換資源有明確決策或待決狀態。
- 延後依賴的缺口在實際受影響位置可見，且可連到後續處理。
- 元件樣式契約與視覺成果實際使用的樣式有映射與驗證；客製範本版本可追溯。
- 文字與視覺成果一致；必要缺口未解或驗證不足時如實標為部分交付。
