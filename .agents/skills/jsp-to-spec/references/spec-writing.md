# 系統設計規格各章撰寫規範

本目錄只維護可重用的轉換原則。任何一次轉換整理出的檔案盤點、SOT 摘錄、原始欄位、介面契約與追溯都是該次參照產物，寫在設定 output_root（預設 `.agents/docs/`）下的最終規格內；不得回填此目錄。

## 1. 範圍與證據

先記錄採用的設定檔及來源／SOT 根目錄，再寫此頁解決什麼使用情境、誰進入與離開、單頁轉換界線及相關文件證據。以責任模組和箭頭說清 UI、頁面規則、外部能力交換什麼資料；不要以技術分層或檔案目錄代替系統流程。目的／角色無證據則明示未決。

## 2. 依賴盤點與邊界

列出目標 JSP 的全部依賴，而非來源根目錄的所有檔名。每列要能回答「哪行引用、如何定位、是否存在、讀了哪一段、對此頁有什麼影響」。列檔後未讀內容的文件不可寫成已分析。細則見 [dependency-boundary.md](dependency-boundary.md)。

## 3. 原始資料與頁面需求契約

先呈現有來源的後端原始資料與介面，再寫消費端抽象需求及映射。逐欄說明輸入／輸出位置、名稱、型別、可空性、限制、轉換與顯示用途；未知明示未知並掛 SP。規格不能只列改名後的前端資料模型而隱去原始證據。依賴反轉原則見 [contracts-and-suspension.md](contracts-and-suspension.md)。

## 4. 系統流程與互動

以使用情境為單位，例如進頁、查詢、驗證、提交、取消。從 UI 事件追到供應端回應，再回到 UI 結果；每步連接資料來源、條件及契約。純顯示 JSP 沒有提交就如實描述供應資料到畫面的流程，不新增服務呼叫。此章是規格主軸，不是開發任務順序。

## 5. 規則、資料與 UI 結構

將流程用到的判斷、分支優先、迴圈、計算及欄位規則明確列出，讓讀者無須讀 JSP 語法也能實作。再依實際畫面區域列結構、資料、可見性與操作。原始條件可在證據欄定位，不作唯一邏輯說明。語意原則見 [semantic-extraction.md](semantic-extraction.md)。

## 6. 畫面狀態與靜態視覺規格

先解釋條件的獨立／互斥關係、可達性與等價分類；狀態表逐列連結 HTML、固定示例資料及觸發流程。不同結果區上顯示相同錯誤提示，若背景畫面不同仍為不同狀態。示例不冒充原始資料。HTML 細則見 [static-visuals.md](static-visuals.md)。

## 7. Suspending points

用可回答的問題表達未知，而非「日後處理 API」等工作計畫。每項指出依賴／契約、既知／未知、影響範圍、暫時畫面、解除所需原始證據與驗證方式。若所有項目解除，附來源證明而非直接刪去缺口歷史的影響說明。欄位規則見 contracts-and-suspension。

## 8. 追溯與驗證結果

從來源行號覆蓋每個行為到規則、流程／契約及狀態，無視覺變化者明示原因。記錄真正執行的檢查與限制，並與第 1 章的完成狀態一致。驗收規則見 [acceptance.md](acceptance.md)；不得以模板填滿或腳本通過代替語意驗證。
