# 交付驗收

以下是執行者的驗收指引，不另輸出 checklist／task 文件。結果摘要寫在規格最後一節。

## 語意與邊界

- 呼叫只需 jsp，來源／SOT／產物位置取自固定設定。單一 JSP 為轉換目標，但已主動查找並讀取相關文件；先盤點再定向讀取，沒有以單頁範圍拒讀其他 JSP、腳本或資料供應文件。依賴表涵蓋相關引用，未將列檔宣稱為全檔內容審查。
- 所有目標 JSP 的條件、迴圈、事件、資料讀寫、格式化、表單欄位、導航、權限與錯誤均有規則或具體 SP。無「依規則處理」等空泛替代。
- 每個流程包含輸入來源、前置條件、判斷順序、介面傳遞、回應與 UI 結果。資料流方向與轉換不遺漏；內嵌腳本未被當成範圍外文件忽略。
- 每個對外依賴有原始證據及頁面需求契約；未決欄位沒有被假定型別／端點／狀態碼填滿。SOT 衝突已掛 SP。
- 規格以自然語言、決策表與資料表表達，沒有框架語法、套件 API 或元件實作要求。原始端點與欄位只作契約與證據。
- 每個規則連到來源行號與流程／狀態；沒有 UI 變化的規則可註明不適用 HTML，但不能省略行為。來源未知不可宣稱已覆蓋。

## 狀態與視覺

- 所有可達且視覺不同的狀態各有 HTML；分組有明確等價理由，未合併畫面不同的獨立條件組合。
- 狀態資料符合前置條件；預設值、錯誤文案、資料列與操作可用性和規格一致。
- HTML 不含執行程式、未展開模板、外部服務／資源或表單提交；斷網可見全部固定內容。
- 規格狀態表連到每一份 HTML，每份 HTML 有唯一 `data-state-id`。產物位於設定 output_root，最終頁面目錄只包含一份 spec.md 與需要的 HTML。
- 逐一記錄靜態腳本驗證與瀏覽器視覺檢查的實際結果。沒有做過的檢查標「未執行」與限制；不聲稱通過。

## 完成判定

未解除 SP 的影響、解除所需證據及暫時畫面明確列出。「邊界已規格化，依賴待確認」是有效的有界交付狀態，但不是原系統完整等價的保證。無未決且全部已知規則覆蓋，才可標「單頁範圍完整」。最終回覆必須連結實際規格與 HTML，不能只有流程規劃或工作摘要。
