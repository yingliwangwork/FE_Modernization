# 外部 SOT、依賴反轉與 suspending points

依賴反轉在此表示：頁面流程依賴「消費端需要的能力與資料契約」，供應端以既有資料／介面映射滿足它。不表示重寫後端、把 JSP 直接換成 API 呼叫，或忽略既有線路格式。

## 先列證據，再列頁面需求

每個 `C-*` 契約分為兩層：

1. **原始供應資料／現有介面**：來源文件與章節／行號、版本（有才寫）、供應時機、request／response／session 等原始位置、原始欄位路徑、型別、可空性、單位／代碼、預設、精度、限制、錯誤。既有 HTTP 介面記錄 method、path、content type、參數位置、線路名稱、回應形狀與已知狀態碼；頁面 render model 不捏造成 HTTP API。
2. **頁面需求契約**：能力名稱、觸發者、輸入輸出、每欄用途、原始資料映射、已知驗證、成功／失敗如何影響規則與狀態。HTTP 等既有協定是外部邊界證據，不指定頁面採用何種框架／客戶端技術。

每項事實標示 `已觀察／SOT證實／消費端需求／未決`。例如 JSP 只迴圈讀取 `orders`，可推得「此頁需要可逐筆讀取的集合」；不能宣稱後端回傳 JSON、某個 status code 或某種 ORM 實體。

若存在明確 SOT，忠實記錄相關原始結構；若不存在，原始型別、可空性、欄位限制、API 回應等未知項就寫未決，另列最低消費端要求。不能為填滿表格編造完整 schema。僅示範資料使用虛構值，並標為「視覺示例，非 SOT」。

JSP 與 SOT 不一致時並列兩者證據，不自動判定其中一方正確；對受影響映射掛 SP。若只給 SOT 未給 JSP 使用方式，不能增加該頁原本沒有的功能。

## suspending point 格式

每個 `SP-*` 必須包含：

| 欄位 | 內容 |
| --- | --- |
| 邊界與證據 | 來源引用、依賴 ID、契約 ID、對應原始行號 |
| 已知事實 | 目前能證實的輸入、觸發、輸出位置 |
| 未知問題 | 一個可被證據回答的明確問題，不寫「待實作」 |
| 影響 | 哪些欄位、規則、流程、狀態或 HTML 區塊無法確定 |
| 暫時表達 | 規格／HTML 如何標示未知；不能暗示功能已完成 |
| 解除所需證據 | 需要哪份原始契約、資料範例、片段輸出規範等；不編出負責人或期限 |
| 解除驗證 | 取得證據後要比對的欄位、條件與行為 |
| 狀態 | `未解除`，或有實際證據才標 `已解除` 並附引用 |

局部依賴未決只懸置相關斷言，其餘規格與畫面照常交付。使用者只需指定 jsp；來源／SOT／output_root 由固定設定取得，不要求額外參數。應先在設定來源內查找並讀取相關文件，不能因它不是使用者提供的 JSP 就直接標缺件。只有目標未提供、定位歧義、不可讀或設定無效時才詢問必要資訊，不假造轉換結果。

## 單頁閉合條件

每個「UI 事件 → 頁面規則 → 外部能力 → 回應 → UI 結果」的箭頭都必須有契約、明確資料或 SP。只說「呼叫後端」「取得清單」「顯示錯誤」而沒有資料來源、條件、回應與畫面位置，不算規格。
