# JSP 行為轉為技術中立規格

完整閱讀目標 JSP，包括內嵌 HTML、CSS、JavaScript 與 scriptlet。引用原始行號，建立規則與畫面之間的追溯；不可只根據畫面外觀或標記名稱摘要。

## 必須還原的語意

| 來源 | 規格應描述 |
| --- | --- |
| 條件顯示、choose／when／otherwise | 判斷資料來源、精確運算／空值語意、分支優先順序、各分支可見／可用內容；獨立 if 可以同時成立，不能擅改為互斥 |
| forEach／巢狀迴圈 | 集合來源、既有順序、每筆欄位映射、索引用途、空集合結果、分組／總計與邊界；沒排序就不能新增排序 |
| EL、Bean、scope、scriptlet | 輸入來源與 scope、預設值、計算、讀寫順序、短路與型別轉換；名稱相同而 scope 不同不可合併 |
| 輸出、格式化、訊息資源 | 原始值 → 顯示值、精度、日期／時區、空白、跳脫或允許的格式內容；未知文案鍵不可猜全文 |
| 表單與隱藏欄位 | 輸入型別、必填／長度／格式、初始／保留值、可編輯性、提交條件、送出欄位及值來源；disabled 與唯讀的提交行為差異 |
| 內嵌事件與腳本 | 觸發事件、檢查順序、條件、取消／繼續、焦點／提示／顯示變更、請求、回應處理；外部函式未知部分掛 SP |
| 連結、提交、forward／redirect | 觸發時機、目標能力／目的地、攜帶資料、留在頁面或離開；區分初始供應資料與提交後的回應 |
| 權限及錯誤 | 顯示／操作限制與其資料依據、錯誤觸發及原文、重試／保留輸入；僅隱藏按鈕不能推論服務端授權已存在 |

「空值」「空字串」「空集合」「零」「false」按原來語意分辨；例如 JSP 的 `empty` 不是數字等於零。原始邏輯有矛盾或缺陷時，描述可觀察事實並標記問題，不悄悄修正成期望行為。

## 表達方式

錯誤：`c:if 改為 v-if；建立 React state 及 fetch hook。`

正確：`R-02：可編輯旗標為真時顯示「儲存」操作；否則不顯示。旗標由 C-01 的原始欄位 canEdit 提供。點選後先依序執行 R-03、R-04，通過才將輸入值交給 C-02。`

規格正文以頁面所需能力、自然語言與資料表表達。來源語法只放證據欄作定位，不當成新實作設計。可以用「所有條件皆成立」「依序取第一個成立分支」或技術中立決策表，避免把原始 expression 直接貼成唯一的行為說明。

模組依責任分為顯示區域、頁面協調、驗證／顯示規則、外部能力邊界即可；名稱依該頁實際內容決定，不強迫新增不存在的中介服務、儲存層或前端架構。

## 狀態與覆蓋

由控制流程列出可達狀態，包含資料有無、條件顯示、編輯權限、驗證結果與來源已有的回應分支。對獨立條件的同時成立情形也需驗證。只有畫面內容／結構／可用操作不同才新增視覺狀態；純資料筆數差異可用代表值，並在規格說明等價分類。

不可使用任意狀態數量上限截斷覆蓋。多條件組合若畫面不同且可達，分別產出；無法證實可達的組合標未決，不偽裝成既有畫面。未知外部行為的分支可用明示未決區塊，但不能發明成功、失敗或 loading 訊息。
