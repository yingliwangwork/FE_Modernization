# 逐狀態硬編碼 HTML

每個 `S-*` 對應一份獨立 `.html`，完整寫出該狀態的文字、資料列、訊息、欄位值、勾選與按鈕可用性。可在製作時使用工具協助寫檔，但交付的 HTML 必須已展開，不能在載入時以程式、模板引擎或網路資料產生內容／切換狀態。

- 保留來源可證實的區域順序、欄位名稱、標籤、表格欄、文案與操作。可讀到直接引用的樣式／資源時依據其規則呈現；缺少時採最小可讀版面並標示視覺依賴未決，不宣稱像素一致。
- 使用標準 HTML 與內嵌 CSS；不加入框架、script、inline event handlers、模組、iframe、外部 stylesheet、遠端字型或動態資料。每份 HTML 可離線開啟；已核實的點陣圖片可內嵌為 data URL，若無法內嵌且需增加外部圖片檔，改以明示缺圖區塊並記 SP，不偷偷增加交付物。
- 表單動作使用 `type="button"` 的靜態按鈕；不送出、不連線原始服務，不以 `onclick` 或 JavaScript 模擬流程。原行為在規格精確描述。可用普通連結導向另一份狀態 HTML 作審閱導航，但需標明這是規格導航而非原功能；不得用單一 HTML 切換多狀態。
- `body` 設 `data-state-id="S-01"` 等唯一 ID，與狀態表及檔名一致。頁面註記列出狀態與「視覺示例資料」，和原有業務文案分開；未知區塊顯示 `SP-*：未確認的內容`。
- 示例值需符合已知條件與型別；空集合狀態不放假資料列，唯讀狀態不出現可提交操作，驗證失敗必須呈現來源實際的提示方式（例如對話提示可另以註記區呈現其固定文案）。
- 預設使用 `<label>`、表格標頭、可辨識焦點與基本對比；避免為改善外觀擅增原頁沒有的操作、欄位或流程。

狀態表需明確寫出所用等價分類、哪些條件可同時成立及需各自呈現的組合。未知片段不阻止已知主畫面靜態呈現，但不得用空白掩蓋缺件。

有瀏覽器能力時逐檔檢查：內容完整、沒有溢出遮擋、條件區塊正確、規格連結有效、離線可見。截圖與暫存驗證資料留於 session／系統暫存，不加入最終交付目錄。
