# 前後端權威分工

**職責**：選定各類主張的權威、版本及衝突處理。產物位置見 [backend profile](./backend-profile.md)，轉寫方式見 [API 規則](./writing-rules.md)。

## 權威依責任選定

| 主張 | 權威來源 | 另一端用途 |
| --- | --- | --- |
| **UI／共用呈現** | 前端 JSP、script、style、include、元件與執行觀察 | 後端說明資料與結果，不決定版面或互動 |
| **API 精確交換** | 指定版本的後端轉換產物 | 前端提供消費需求，不新增或改名 wire 欄位 |
| **業務／受信任狀態** | 後端業務規格、已確認設計與適用實作契約 | JSP 證明 legacy 行為或遺漏，不證明目標 API 已支援 |
| **前後端映射** | 各端責任內的證據共同成立 | 任一端缺證據開缺口，不以名稱相似作映射 |
| **未承接 legacy 邏輯** | JSP 作舊行為證據，目標後端需承接紀錄 | 形成 HANDOFF，不直接升格為目標 API |

- **版本獨立**：前端入口與 backend_root、後端產物、版本／雜湊及環境各自鎖定。
- **基準不可混用**：不同發布版本、legacy 語意、設計稿與 stub 不拼成一份現行契約。
- **必填分開**：UI 操作限制不修改 API 接受條件；後端必需資料在前端無合法來源時開介接缺口。
- **訊息分工**：前端負責顯示位置及固定映射；後端負責回傳文字、代碼及動態值。直接顯示後端文字時保留原文，差異不以文案整理掩蓋。

## 後端基準與衝突

| 情況 | 處理方式 |
| --- | --- |
| **指定發布契約** | 優先使用使用者或交付紀錄指定基準，核對版本及適用範圍 |
| **規劃／設計版本** | 標為設計契約，不宣稱已部署 |
| **只有方法規格** | 可確認業務語意，不推導 HTTP path、序列化名稱或 envelope |
| **只有 controller 設計** | 使用已記載內容；共通回應缺失另開 TODO |
| **同版文件與實作不符** | 登錄雙方 E-ID 及待裁決 TODO，不以修改時間或程式較新自行取捨 |
| **已有基準選定紀錄** | 用於目標契約；與 legacy 差距仍留痕，不自動授權改變 UI |
| **基準未取得** | 只限制相應 API／業務主張；已知前端分析繼續，未知操作不填假 path／schema／成功例 |

- **方法參考不是能力證據**：`.github` 指導文件、skill、範本與示例不能證明本頁目標能力。
- **環境與部署分開**：未交付呼叫環境記環境缺口，部署狀態另列未確認。
- **版本回查**：依 [續作流程](../../guides/workflow.md#驗證與續作) 保存歷史並核對受影響映射。
