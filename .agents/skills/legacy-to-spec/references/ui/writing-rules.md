# UI 規格與高保真原型

**職責**：定義 AI 可讀 UI 契約及其原型映射。樣式細節見 [style spec](./style-spec.md)，執行關卡見 [workflow](../../guides/workflow.md)。

## AI 可理解的 UI 規格

使用 [UI 模板](../../templates/spec/ui-spec.md)，以技術中立契約描述畫面，不依賴 HTML、Angular、React 或原型生成。

| 契約組 | 記錄內容 |
| --- | --- |
| **SCR／UI／CMP** | 畫面、資訊層級、元素、操作及共用元件本頁用法 |
| **FLOW／BOUND** | 觸發、前置、條件、反應、結果、後置及邊界交接 |
| **DATA／ST／TR／BR／MSG** | 資料、狀態、轉移、限制及訊息 |
| **STYLE** | 有證據的視覺要求與狀態差異 |
| **US／UC／AC 引用** | 對應需求、使用情境及可觀察驗收定義 |

- **精確條件**：不只寫「可查詢」，而要描述觸發、資料、判斷與可見結果。
- **事件完整**：初始化、顯示／隱藏、啟用／停用、焦點、快捷鍵、排序、回填、callback、取消、計時、錯誤與離開按來源分別記錄。
- **作用範圍**：保留註冊對象、順序與生命週期；原始符號映射在 evidence，不以函式名稱代替需求。
- **穩定識別**：前綴與版本追溯依 [evidence](../../guides/evidence.md#穩定-id)。

## 高保真原型與契約映射

原型使用 [prototype 模板](../../templates/prototype/prototype.html) 或相容客製模板，**供使用者對照已確認畫面及操作**。

- **視覺**：還原資訊密度、區塊順序、對齊、尺寸、文字、色彩、字型與有證據的狀態。
- **互動**：每個操作與狀態可回到規格 ID 及 E-ID，反向核對應實作契約都有展示與檢查。
- **metadata**：映射到 `data-ui-id`、`data-flow-id`、`data-state-id` 或實作索引；不得為填欄位虛構產品 ID。
- **模板邊界**：scaffold 或只可點擊線框不是高保真成果，預設樣式不能當產品證據。
- **差異處理**：來源／規格／原型不一致時先開 TODO、核對權威、修訂並審閱規格，再改原型。

## 資料、服務與展示替身

- **合成資料**：明示示例，不用真實敏感資料、權杖或使用者資訊。
- **服務邊界**：不呼叫真實 API、不提交資料、不產生真實業務副作用；只展示已確認交接。
- **Mock 邊界**：只呈現已確認契約，不能推導服務能力或未知結果；未知不顯示成功，也不刪已知觸發。
- **本地資產**：不預設 CDN、追蹤或遠端字型；框架依 instruction 使用本地工具鏈，不任意新增套件。

## 可見文字與審閱工具

- **文字保真**：保留原文、格式、訊息對象、觸發與消失時機，不自行改成較友善文案。
- **工具分離**：導覽、狀態切換器與說明標為 review tooling，不混入產品 UI，不改產品事件。
- **使用說明**：記規格基線、技術棧、啟動、已實作範圍及限制，不把 planning／log 塞入產品畫面。

## 實作驗證引用

- **樣式映射**：依 [style spec](./style-spec.md) 核對 STYLE → 元件／樣式 → AC。
- **完成判定**：依 [原型驗收](../../guides/acceptance.md#第二階段原型完成關卡) 執行真實技術棧的瀏覽器檢查。
- **保存位置**：實作草稿、review 與最終產物依 [輸出分類](../../guides/workflow.md#輸出分類與相對連結)，載入成功不等於契約驗證完成。
