# 分階段驗收

**職責**：定義各里程碑的可檢查條件、驗證紀錄及交付判定。執行模式、狀態與輸出位置依 [workflow](./workflow.md)。

## 共通檢查

- [ ] **來源**：唯一入口、版本、解碼依據、直接／相關間接依賴及分析邊界可定位。
- [ ] **追溯**：主張連到 E-ID，未知／衝突連到 TODO-ID，實際來源與案例都有覆蓋去向。
- [ ] **行為**：保留事件範圍、生命週期、時間、順序、中間狀態、取消、異常及副作用。
- [ ] **權威**：前後端映射有兩端依據；來源事實、設計承諾、HANDOFF 與展示替身可區分。
- [ ] **適用性**：不把未取得當成不適用，不以 optional 免除必要規格。
- [ ] **文件分離**：契約不混入工作排程、任務進度或實測 log；草稿不冒充最終產物。

## 第一階段：第一版交付檢查

**檢查對象**：AI 可理解的入口 UI／行為第一版。其他適用文件與依賴契約可尚待補齊。

| 檢查項 | 通過條件 |
| --- | --- |
| **實際文件** | draft 中有可讀第一版及版本；不是空模板或只有計劃 |
| **依賴與影響** | 核對已取得文件及版本；未取得項、停止邊界與影響有記錄 |
| **已知契約** | 已知畫面、流程、資料、狀態、訊息、樣式及邊界需求有證據 |
| **AI 可讀性** | 使用穩定 ID、結構化欄位；流程有觸發、前置、條件、反應、結果及後置 |
| **局部缺口** | 未知端點、HTTP method、承接映射與衝突各有具體 TODO 及索引連結 |
| **狀態回報** | 第一版連結、版本、已完成、剩餘 TASK、前置、可執行性與阻塞均已列出 |
| **選擇一致** | 依 workflow 等待使用者選擇或 auto=all 直接續作；已有授權不重問 |
| **交付限制** | 明示草稿／部分規格，檢查在 review；不提升為完整規格 |

**結果**：通過即可交付第一版；TODO 或其他文件未齊備不阻塞此里程碑。

## 第一階段：完整規格完成關卡

| 適用產出 | 必須確認的內容 |
| --- | --- |
| **PRD** | 有證據的意圖、角色、User Story **及** Use Case、主／分支／異常流程、非目標與 AC |
| **UI spec** | UI／FLOW／DATA／ST／TR／BR／MSG／STYLE、觸發與結果可追溯 |
| **API spec** | 真實欄位、型別、順序、錯誤、後端權威版本、前端映射與 HANDOFF |
| **BDD** | 可觀察 Given／When／Then 與規格／證據 ID 一致，未知不寫成已確認或已通過 scenario |
| **跨文件** | PRD ↔ UI/API ↔ BDD ↔ E/TODO 一致，沒有重複或矛盾需求 |

- [ ] **文件齊備**：適用必要文件已完成，必要契約及驗證無未解缺口。
- [ ] **完整審閱**：review 指向確切版本，有真實結果及限制。
- [ ] **交付基線**：通過後提升到 deliverables，記錄版本與 SHA-256，重算相對連結。
- [ ] **部分判定**：任一必要文件、契約或驗證不足時仍為部分交付，保留 draft 及待辦。

**不需原型才能完成規格**：CSS、JavaScript、設計 token 與瀏覽器原型測試不屬未選原型時的規格關卡。

## 第二階段：原型啟動關卡

- [ ] **授權**：已選 prototype、直接要求原型或 auto=all。
- [ ] **基線**：適用完整規格已審閱，有可定位版本與 SHA-256；draft／planning／review 不能代替規格。
- [ ] **必要契約**：所需流程、資料、狀態、訊息及樣式均有確認依據，必要缺口已處理。
- [ ] **技術棧**：已讀生效 instruction，記錄版本與選定棧，模板及啟動方式相容。

## 第二階段：原型完成關卡

| 檢查項 | 通過條件 |
| --- | --- |
| **行為映射** | UI／FLOW／ST／STYLE 對應已審閱規格；觸發、取消、分支、轉移、訊息與副作用邊界一致 |
| **高保真** | 密度、區塊順序、對齊、尺寸、字型、色彩及狀態有逐項對照，不以通用骨架／線框宣告完成 |
| **呈現證據** | 文字、焦點、可用性及樣式有證據；未知視覺保留 TODO，不用慣例補造 |
| **展示邊界** | 合成資料及替身明示，不用真實敏感資料、真實服務或業務副作用 |
| **瀏覽器驗證** | 依實際技術棧執行載入、資產、console、已知互動、狀態與視覺對照 |
| **使用說明** | 規格基線、啟動方式、已實作範圍及限制清楚；審閱工具與產品 UI 分離 |
| **交付** | 通過後提升實作至 deliverables/prototype；截圖、log 與結果留 review |

## 驗證紀錄與完成宣告

| 每筆 V-ID 欄位 | 必記內容 |
| --- | --- |
| **識別** | V-ID、AC-ID、規格版本及相關 E-ID |
| **條件** | 環境、角色、資料、前置條件及方法 |
| **對照** | 預期、實際結果、截圖／log 及證據位置 |
| **結果** | pass／fail／not-run、原因、限制及後續 TODO |

- **案例不是實測**：寫出 AC／BDD 不代表已執行，不能複製預期充當結果。
- **無法執行**：記 not-run、原因及驗證缺口，不寫成通過。
- **續作檢查**：新增證據或改版後重查受影響契約，解決依據及原紀錄可追溯。

| 交付宣告 | 必須符合 |
| --- | --- |
| **第一版交付** | 第一版檢查通過；仍屬草稿／部分，不是原型基線 |
| **完整規格完成** | 適用文件、必要契約、驗證及完整審閱全部通過 |
| **部分規格交付** | 列缺口、影響、剩餘任務與限制；不能當合格原型基線 |
| **原型未選用** | 無空目錄，不影響規格是否完成 |
| **原型完成／部分** | 按原型關卡實際結果判定，不把原型失敗改寫為規格失敗 |

**案件狀態另行回報**：使用 workflow 定義的狀態，列已完成、剩餘、阻塞及模式；不能用部分任務完成宣告結案。
