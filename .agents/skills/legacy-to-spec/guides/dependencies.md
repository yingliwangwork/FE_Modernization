# 依賴與缺口回補

**職責**：定義依賴適用性、局部 TODO 及證據回補。執行與任務授權依 [workflow](./workflow.md)，主張與 ID 依 [evidence](./evidence.md)。

## 依賴盤點與重用

| DEP 欄位 | 必記內容 |
| --- | --- |
| **定位** | DEP ID、來源位置、角色、直接／相關間接引用 |
| **版本** | 原件版本／雜湊、已查範圍與停止邊界 |
| **影響** | 本入口使用情境及受影響契約 ID |
| **既有文件** | PRD、spec、BDD 或共用契約實際位置與版本 |
| **適用性** | 入口、角色、資料、情境與生命週期是否匹配 |
| **權威與缺口** | 可支撐內容、未取得項、關聯 E／TODO 與查證狀態 |

- **可重用**：引用已核對版本及章節，只描述本入口用法，不重複翻新共用契約。
- **不可只比名稱**：路徑或名稱相同不代表契約適用；列出引用不等於全部依賴已盤點。
- **來源性質**：原型、草稿或 review 不是已確認服務能力的證據；已有證據仍須核對範圍及權威。
- **缺少文件**：保留已知觸發、資料、分支與結果，只對未知部分開 TODO，不阻塞入口第一版。
- **獨立翻新**：讀取依賴查證本入口不等於翻新另一入口；另列範圍、影響、順序及驗收條件，依 workflow 取得所需授權。

## 局部 TODO 與缺口索引

**每個受影響契約位置都要看得見缺口**；總表不能取代局部標記。

```markdown
{{ todo: TODO-001 | 尚未取得後端路由映射 }}
```

| 缺口欄位 | 必記內容 |
| --- | --- |
| **TODO／類型** | 穩定 ID；未知、衝突、缺依賴或未驗證 |
| **已知內容** | 相關 E／DEP、已確認行為及各方衝突證據 |
| **具體未知** | 缺少哪項條件、映射、結果或權威版本 |
| **影響位置** | 各受影響 US／UC／UI／FLOW／BOUND／API／HANDOFF／DATA／ST／STYLE 等位置 |
| **解決條件** | 待取得來源、重現情境、需確認者及必要驗證 |
| **關聯 TASK** | 下一個具體任務；進度與授權引用 planning |

- **保存位置**：完整缺口索引在 `history/evidence/`；局部標記旁連到其實際章節。
- **不要裸占位**：不能只留 `{{ todo }}`、空欄或未填模板內容。
- **沿用已有 ID**：既有 `TODO-ID：具體缺口` 可沿用；新增文件沿同一 ID 補齊局部標記。
- **表格 escaping**：標記放 Markdown 表格時，分隔符 `|` 寫為 `\|`。
- **進度分離**：任務順序、授權及執行狀態留 planning；實測結果留 review。
- **未知結果**：BDD 不把未知 Then 寫成成功 scenario；原型不以 mock 宣稱依賴已承接。

## 端點與方法未知

| 項目 | 正確處理 |
| --- | --- |
| **legacy 提交目標** | 有來源就記錄為舊交換事實，不直接當成目標 API |
| **實際端點／Path** | 未取得路由映射時開具體 TODO |
| **HTTP method** | 未取得傳輸方式時另開 TODO，不因查詢推定 GET |
| **後端處理方法** | 未確認承接映射時記缺口，不與 HTTP method 混用 |
| **前端呼叫函式** | 來源符號留 evidence；規格保留中立觸發與行為 |

```markdown
實際端點：{{ todo: TODO-001 | 尚未取得後端路由映射 }}
HTTP method：{{ todo: TODO-002 | 尚未取得傳輸方式證據 }}
```

**已知內容先完成**：同一操作的觸發、輸入及已知反應仍保留；只有真正未知的欄位標 TODO。

## 取得證據後回補

1. **核對新證據**：確認版本、角色、情境與權威；衝突保留雙方證據，不自行裁決。
2. **補齊契約**：沿原 TODO／契約 ID 更新所有受影響文件及映射。
3. **保存歷史**：保留原缺口、被取代證據與解決依據，不刪歷史掩蓋差異。
4. **更新任務**：記錄關聯 TASK 的結果及剩餘工作。
5. **重查影響**：重新審閱受影響規格與驗證；必要時更新已選原型。

**關閉條件**：取得該問題所需證據並完成必要驗證。僅建立依賴文件或寫出 HANDOFF，不代表缺口已解決。
