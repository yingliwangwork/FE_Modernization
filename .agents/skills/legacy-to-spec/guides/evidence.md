# 證據與契約識別

**職責**：定義主張分類、證據欄位、語意轉譯與 ID。權威判定見 [authority](../references/api/authority.md)，缺口處理見 [dependencies](./dependencies.md)。

## 主張分類

| 分類 | 可描述內容 | 必要依據 |
| --- | --- | --- |
| **已證實** | 指定條件下的行為、規則或文件所述意圖 | 可定位來源、可重現觀察或確認紀錄；引用 E-ID |
| **未知** | 尚未確認的條件、反應、意圖或映射及其影響 | TODO-ID 連到具體待查問題 |
| **衝突** | 各來源不一致之處，不自行選定結論 | 各方 E-ID 及待裁決 TODO-ID |
| **不適用** | 本範圍確認不涉及的能力 | 檢查範圍、理由與 E-ID |

- **推測不是契約**：加上「可能／應該」也不能當正式行為；追查線索只留待驗證缺口。
- **可取得性不是存在性**：未取得文件、未列操作、未提供環境，不等於能力不存在、停用或未部署。
- **部署另需證據**：設計或展示文件不能證明已部署或未部署；缺呼叫環境只記測試環境缺口。
- **未知只限未知部分**：不知分支是否被選用，不代表已知分支反應可刪除。

## 證據登錄

證據索引放在 `history/evidence/`。每項 E-ID 記錄**來源性質、版本、定位、適用範圍、支撐主張與限制**。

| 來源類型 | 定位及重現欄位 |
| --- | --- |
| **原始碼** | 相對路徑、版本／雜湊、原始行號或穩定符號、精簡摘錄、支撐與不能支撐的主張 |
| **轉碼副本** | 原件、解碼依據、轉碼方式及原始行號對應；保留原件 |
| **執行觀察** | 環境、時間、角色、前置資料、操作、實際結果、截圖／錄影位置 |
| **既有文件** | 文件／章節、版本／日期、來源性質、適用入口與情境 |
| **人工確認** | 可定位紀錄、日期、確認者角色、確認範圍及變更依據 |

- **原始行號**：依 bytes 的物理行基準，末行不得超過 inventory 行數；結尾換行不額外算一行，不以手工計數取代 metadata。
- **逐項追溯**：每項功能主張都有證據；一列有不同依據時分列，不以章首單一引用涵蓋整份文件。
- **觀察範圍**：單一角色、資料或環境的結果不能推廣到其他情境。
- **註解與名稱**：是線索；可引用註解為「文件所述意圖」，不能據此斷言執行結果。
- **否定主張**：只有可定位的否定證據能支撐不存在、停用或未部署。
- **原始碼與觀察**：各自保留；有差異依權威及衝突規則處理，不預設某一類永遠優先。

## 技術中立的轉譯

| 內容 | 規格中的表達 | 保留位置 |
| --- | --- | --- |
| **UI 行為** | 觸發、條件、反應、可見結果、後置狀態 | UI spec |
| **資料語意** | 概念型別、方向、格式、單位、必填、允許值、缺省及空值意義 | UI／PRD；精確 wire 另見 API spec |
| **API 傳輸** | 原件欄位、型別、method、path、格式及代碼 | API spec，依 [API 規則](../references/api/writing-rules.md) |
| **來源符號與步驟** | 實作定位與契約映射 | history/evidence |
| **可辨識文字／格式** | 原文、代碼、檔案格式或跳轉目的本身屬契約時保留 | 對應契約位置 |

- **不可跨越證據**：有送出按鈕不等於已寫入；驗證函式名稱不等於已知檢核；隱藏按鈕不等於服務端已授權。
- **保留已知反應**：來源證明 A 變更後清空 B，就描述清空；選項如何取得未知時只標該部分 TODO。
- **訊息分別核對**：原文、標點、動態值、觸發及順序逐項保留，不因文字相似合併不同事件。
- **領域規則**：引用本輪適用 reference 或專案權威文件，核對術語、版本與範圍；缺少依據不生成業務知識。

## 穩定 ID

**scope 內唯一、跨文件沿用同一語意**；跨 scope 用 `<scope-id>/<ID>`。排序不改號，刪除／取代保留對照及依據。

| 前綴 | 代表 | 主要保存位置 |
| --- | --- | --- |
| **E** | 證據 | history/evidence |
| **DEP／LOGIC** | 依賴／混合邏輯盤點 | history/evidence |
| **TODO** | 缺口識別 | 詳情在 history/evidence，局部標記在契約 |
| **TASK／DEC／CHANGE** | 任務／決策／增量變更 | history/planning |
| **V** | 真實驗證執行 | history/review |
| **INT／ACT** | 意圖／角色或觸發者 | PRD／UI spec |
| **US／UC** | User Story／Use Case | PRD |
| **SCR／UI／CMP** | 畫面／元素／共用元件 | UI spec |
| **DATA／BR／MSG** | 資料／規則／訊息 | 對應規格 |
| **ST／TR／FLOW／BOUND** | 狀態／轉移／流程／邊界互動 | UI spec；其他文件引用 |
| **STYLE** | 樣式契約 | UI spec |
| **API／HANDOFF** | API 消費契約／待後端承接責任 | API spec |
| **AC** | 驗收案例定義 | PRD／UI/API spec／BDD 共用引用 |

**格式**：例如 `E-001`、`FLOW-001`、`TODO-001`。STATE／RULE／CASE 可作一般語意名稱，但新增識別碼統一使用 **ST／BR／AC**。
